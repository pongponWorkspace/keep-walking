## 4. ข้อที่ต้องแก้ก่อน build (blocking)

### B-01 ปุ่ม "เข้า" ต้องแสดงสถานะ check-in ตั้งแต่ popup เปิด ไม่ใช่หลังกด
- ตำแหน่ง: flow หัวข้อ 4 ย่อหน้าแรก ("ตอนกด 'เข้า' engine ประเมิน ... เปลี่ยนเป็น `.btn-disabled`"), หัวข้อ 8 แถว Check-in คอลัมน์ loading
- ปัญหา: flow อ่านได้ว่าผู้เล่นต้องกด "เข้า" ก่อนจึงรู้ว่ายังเข้าไม่ได้ ขัด spec R09 และ T1 (popup ขึ้นมาในสถานะ `CheckInPending` ถ้า R07 ยังไม่ครบ) และ tech note 7.4 (`selectCheckInPreview` ทุกครั้งที่ state เปลี่ยน) · ผู้เล่นกดแล้วเจอปฏิเสธคือจังหวะ "ถูกจับผิด" ที่ spec หัวข้อ 1 ห้าม
- แก้: เขียนใหม่ว่า popup เปิดพร้อมสถานะจาก preview ทันที ปุ่ม disable + บรรทัดเหตุผลตั้งแต่เฟรมแรกถ้ายังไม่ผ่าน และเปิดใช้เองเมื่อ preview ผ่าน · การกด "เข้า" เรียก `confirm` ซึ่งยังปฏิเสธได้ในกรณี race (สถานะเปลี่ยนระหว่างแตะ) ให้แสดงผลในบรรทัดเดียวกันโดยไม่ปิด popup · loading ระหว่างรอผล confirm ใช้ spinner บนปุ่มตามเดิม

### B-02 ออฟไลน์ไม่มีผลต่อ "เข้า" และ "ออกเอง" ใน Phase 2
- ตำแหน่ง: flow หัวข้อ 8 แถว `S-02-dungeon-confirm` และ Check-in คอลัมน์ offline, หัวข้อ 9 ข้อ "เน็ตหลุด" (ประโยค "ปุ่มที่ต้องยิง request ... disable"), หัวข้อ 8 แถว `S-03-run` คอลัมน์ offline, wireframe F04-02 เฟรม B5 caption
- ปัญหา: Phase 2 ไม่มี server · confirm และออกเองเป็น `sessionStep` ในเครื่อง ไม่มี request · spec E8 ระบุว่าเน็ตหลุดไม่มีผลใดต่อ run และมีแค่ banner บนแผนที่ · การ disable ปุ่มเข้าตอนไม่มีเน็ตทำให้คนที่เดินมาถึงสวนที่สัญญาณมือถือแย่เข้าเล่นไม่ได้ (ขัด P2 "มาถึงแล้วต้องได้เล่น") และการ disable ปุ่มออกขัด "ออกได้ทุกเมื่อ" · หัวข้อ 9 ยังขัดกันเองในย่อหน้าเดียว
- แก้: ลบการ disable ปุ่มเข้า/ออกและ `common.offlineNotice` ออกจาก popup confirm, check-in และจอ run · จอ run ไม่แสดง banner ออฟไลน์ใน Phase 2 (ไม่มีอะไรที่ผู้เล่นต้องทำ ตาม P4) · คง banner `gps.offline` บนแผนที่ และแผง fallback นำทางตอนออฟไลน์ (tech note 14.2) · ระบุว่าพฤติกรรมออฟไลน์ของ Phase 3 เป็นของ flow F08

### B-03 overlay speed lock: ก่อนมี run ต้องปิดเองไม่ได้ และปุ่มตั้งค่าต้องมี copy key
- ตำแหน่ง: flow D1 ข้อย่อยปุ่ม ("ถ้ายังไม่เข้า run ปุ่มนี้แค่ปิด overlay กลับแผนที่", "`[settings.walkingSafetyLink]`-style ลิงก์ตั้งค่า"), wireframe F04-03 เฟรม D1 (ปุ่ม "ตั้งค่า" เป็นข้อความไทยฝัง ไม่มี copy key)
- ปัญหา: GDD "Anti-cheat" และ "ความปลอดภัยทางกายภาพ" ให้ speed lock "ล็อกการเล่นและขึ้นข้อความ ไม่ใช่แค่เตือน เพราะจะมีคนเล่นระหว่างขับรถแน่นอน" · ปุ่มที่ปิด overlay ได้ก่อนมี run คือปุ่มเล่นต่อในทางปฏิบัติ (คนขับกดปิดแล้วดูแผนที่ต่อ) ขัด R23 และ R21 · ปุ่ม "ออก" ก่อนมี run ก็ไม่มีอะไรให้ออก · ปุ่มตั้งค่าที่อ้าง key "แบบ" ของอีก key ทำให้ build ต้องเดาหรือฝังข้อความไทย (CLAUDE.md กติกา copy)
- แก้:
  1. ก่อนมี run: overlay มีปุ่มตั้งค่าปุ่มเดียว · ระหว่าง run: ปุ่มตั้งค่า + ปุ่ม "ออก" (เข้า popup ยืนยันออกเดิม ซ้อนบน overlay) · ไม่มีทางปิด overlay นอกจากปลด lock (R22)
  2. เข้าตั้งค่าจาก overlay ได้ เมื่อกลับจากตั้งค่าและยัง lock อยู่ overlay กลับมาทันที · ถ้าปลด lock ระหว่างอยู่ในตั้งค่า กลับมาเจอจอตามสถานะตำแหน่งจริง
  3. ระบุ copy key ของปุ่มตั้งค่าให้ชัด (เสนอ key ใหม่ `anticheat.speedLockSettings` ให้ narrative ตั้งคำ หรือใช้ key ชื่อหน้าตั้งค่าที่มีอยู่ ถ้ามี) · ปุ่มไปหน้า `S-22-settings` หน้าแรก ไม่ใช่หน้าย่อย "การเดินและความปลอดภัย" ที่ฝังลึกโดยตั้งใจ
  4. ระบุว่า header ของจอเดิมมองเห็นใต้ overlay หรือไม่ (ดู N-12) ถ้าเห็น ไอคอนตั้งค่าใน header ต้องไม่พาออกจาก lock ไปทางอื่น

  2. เนื้อหา: tech note แสดงชื่อที่ค้นได้ **และ** พิกัดปลายทาง (ข้อมูลสาธารณะของสถานที่) พร้อมปุ่มคัดลอกแยกกัน · clipboard ใช้ไม่ได้ → `<input readonly>` ที่เลือกข้อความไว้แล้ว · flow มีแค่ชื่อ

### B-06 กับดัก check-in หลังกลับจากแอปนำทาง
- ตำแหน่ง: flow A3 `⤷` "เปิดแอปแผนที่สำเร็จ → ... ไม่มีอะไรต้องทำต่อในเกม", A5
- ปัญหา: ระหว่างที่แอปแผนที่อยู่หน้าจอ หน้าเว็บของเกมถูกซ่อนและไม่ได้ sample (GDD "สัญญาณขาดและแอปถูกปิด": v1 บนเว็บหยุดนับเมื่อจอล็อก/ซ่อน) · ลำดับ approach ของ check-in จึงล้ม (tech note 7.2) · ผู้เล่นที่เดินตามแอปแผนที่จนเข้าสวนแล้วค่อยสลับกลับมาจะเจอ `not_enough_trace` ตามด้วย `no_approach_from_outside` ต้องเดินออกแล้วเข้าใหม่ · นี่คือทางหลักของ onboarding นาที 1–3 (pillars 6.1) ไม่ใช่ edge case และ flow ตอนนี้บอกผู้เล่นตรงข้ามว่า "ไม่มีอะไรต้องทำต่อในเกม"
- แก้ (J-6):
  1. แผง A2 (ทั้งสถานะใกล้และไกล) และแผง fallback มีบรรทัดสั้นหนึ่งบรรทัดใต้ปุ่มนำทาง copy key ใหม่ เช่น `nav.returnBeforeArrive` · เจตนา: "ใกล้ถึงแล้วสลับกลับมาเปิดเกมค้างไว้ก่อนเดินเข้าเขต" · ห้ามอธิบายว่าเกมตรวจอะไร (U7) · คำสุดท้ายเป็นของ narrative
  2. แก้ `⤷` ของ A3 ให้ตรงความจริง: ออกไปแอปนำทางได้ แต่ต้องกลับมาก่อนถึงขอบเขต
  3. ไม่เพิ่มกลไกใหม่ (ไม่มี push, ไม่มี geofence, ไม่ผ่อนเงื่อนไข check-in) · ถ้าผู้เล่นพลาด ข้อความ `no_approach_from_outside` เดิมพาเดินออกแล้วเข้าใหม่ได้โดยไม่ลงโทษ
  4. เพิ่มในคำถาม playtest (หัวข้อ 11 ของ flow): สัดส่วนคนที่ใช้แอปนำทางแล้วเจอ `no_approach_from_outside` ตอนมาถึง

### B-07 "นอกระยะ" (B5) ต้องเป็นบรรทัดสถานะ ไม่ใช่ popup ปิดอย่างเดียว
- ตำแหน่ง: flow B5, หัวข้อ 8 แถว `S-02-dungeon-confirm` คอลัมน์นอกระยะ, wireframe F04-02 เฟรม B5
- ปัญหา: popup เปิดเมื่อจอแสดงผลเห็นผู้เล่นอยู่ใน polygon (tech note 7.4) · ถ้า sample ล่าสุดหลุดออกนอก polygon ระหว่าง popup เปิด engine คืน `no_approach_from_outside` (tech note 7.3 ข้อ 4) ไม่ใช่เหตุผล "นอกระยะ" แยก · flow จึงมีสองจอสำหรับเงื่อนไขเดียว และจอ B5 บังคับปิด popup ขัด R06/R09 (ปุ่มเปิดใช้เองเมื่อพร้อม ไม่ต้องปิดเปิดใหม่) · คนยืนขอบสวนที่ GPS ส่ายจะเจอ popup ขึ้น-ปิด-ขึ้นซ้ำ
- แก้ (J-7):
  1. ลบ B5 ในรูป popup แยก · เมื่อเหตุผลคือ `no_approach_from_outside` **และ** sample ล่าสุดอยู่นอก polygon ที่เลือก (ตรวจด้วย geo เพื่อแสดงผล) บรรทัดใต้ปุ่มใช้ `dungeon.outOfRangeTitle` แทน `dungeon.checkinNoApproach` · ลำดับเหตุผลของ R08 ไม่เปลี่ยน (เป็นหมวดย่อยของลำดับ 4)
  2. popup ปิดเองตาม T4 (ออกนอกเขต) เมื่อจอแสดงผลเห็นผู้เล่นอยู่นอก polygon ต่อเนื่องครบเกณฑ์เดียวกับ hysteresis ของ R15 (`config: dungeons.runState.edgeHysteresisSamples` / `edgeHysteresis_m` · ใช้แสดงผลเท่านั้น) ไม่ปิดจาก sample เดียว
  3. แจ้ง narrative ให้แก้ context ของ `dungeon.outOfRangeTitle` (ตอนนี้เขียนว่า "server พบ ... ปิด popup")

### B-08 หน้าสรุป `timeout`: ของอยู่ครบ และใช้ key ใหม่
- ตำแหน่ง: flow หัวข้อ 7 แถว `timeout` ("ครบเท่าที่ยืนยันได้", ใช้ `run.summary.connectionLost` ซ้ำ), หัวข้อ 11 A-P2-F04-T15-4, wireframe F04-04 เฟรม F2

- แก้ (J-4): คอลัมน์ของที่เก็บได้ = "ครบ (หน้าต่างที่ค้างไม่จ่าย ตาม F05-R21)" · เพิ่ม key ใหม่ `run.summary.timeout` ในหัวข้อ 10.1 เจตนา "อยู่นอกเขตนานเกินไป run จบ ของอยู่ครบ" (body ถ้ามีเป็น key ใหม่เช่นกัน) · ปิด A-P2-F04-T15-4 · แก้ wireframe F2

## 6. สิ่งที่ผ่านและไม่ต้องแตะ

- popup confirm ต้องกด "เข้า" ทุกครั้ง ไม่มีเข้าอัตโนมัติ (R02) · ยกเลิกไม่มีผล (R06) · เลเวลนอกช่วงไม่บล็อก (R32)
- dungeon ปิดไม่มีปุ่มเข้า แสดงเวลาเปิดถัดไป · แผงนำทางวางเวลาเปิดถัดไปเหนือปุ่มนำทางและยังกดนำทางได้ (R27, R38)
- ระยะมีชิป "เส้นตรง" ทุกจุด ปัดขึ้น ไม่มีเส้นหรือ polyline บนแผนที่ ไม่มี turn-by-turn (R34, R36, A4)
- run state เปลี่ยนจากตำแหน่งเท่านั้น ไม่มีปุ่มเปลี่ยนสถานะนอกจากออกเอง (R19) · 4 สถานะแยกได้ด้วยไอคอน+คำ ไม่ต้องอ่านตัวเลข · กลับ Active นาฬิกาไม่รีเซ็ต (D-094)
- ปิดทำการระหว่าง run จบ `dungeon_closed` ทันทีทุกสถานะ ไม่ต้องเดินออก (R30, E11)
- speed lock: overlay ทับทุกจอ ไม่มีเสียงวน สั่นครั้งเดียว ปลดเองไม่ต้องกด (R22, R23) · ข้อความไม่อธิบายวิธีวัด (U7)
