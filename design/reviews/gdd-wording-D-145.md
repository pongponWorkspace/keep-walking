## 1. จุดที่ขัดจริง

GDD "การเข้าสู่ระบบ" มีสองประโยคเรื่อง password ที่อ่านแล้วต่างกัน:
- ย่อหน้าแรก: "ไม่มีให้ตั้ง password" → **ขัด D-145 ตรงๆ**
- บรรทัด "ไม่เอา": "email + password เป็นทางหลัก" → **ไม่ขัด** D-145 เพราะ D-145 วาง email + password เป็นทางรอง Google/Apple ยังเป็นทางหลัก

ดังนั้นแก้ให้น้อยที่สุดได้: เปลี่ยนย่อหน้าแรก คงเหตุผลเดิม (mobile-first ห้ามบังคับจำรหัส) และคงบรรทัด "ไม่เอา" เกือบทั้งหมด
หลักที่ใช้ตัดสินถ้อยคำ: GDD "หลักการที่ใช้ตัดสินทุกข้อขัดแย้ง" ข้อ 1–5 ไม่ครอบเรื่อง login โดยตรง · ใช้เหตุผลของ GDD เองในหัวข้อนี้ (อย่าไล่คนกลับตั้งแต่หน้าแรก) และ NN-7 (PDPA เก็บเท่าที่จำเป็น) เป็นกรอบ

## 2. ส่วน A — หัวข้อ "สถาปัตยกรรมเทคนิค > การเข้าสู่ระบบ" (D-145)

### A1 ย่อหน้าแรก

ก่อน:
> ใช้ Google กับ Apple login เป็นหลัก ไม่มีให้ตั้ง password เพราะเกม mobile-first ที่บังคับให้จำรหัสคือการไล่คนกลับตั้งแต่หน้าแรก

หลัง (เสนอ):
> ใช้ Google กับ Apple login เป็นหลัก เพราะเกม mobile-first ที่บังคับให้จำรหัสคือการไล่คนกลับตั้งแต่หน้าแรก มี email + password เป็นทางรองสำหรับคนที่ไม่มีหรือไม่อยากใช้บัญชี Google/Apple (เข้าสู่ระบบ, สมัคร, ลืมรหัสผ่าน) ทางรองต้องอยู่ต่ำกว่าปุ่มหลักบนจอ login และไม่มีจอไหนบังคับให้ตั้ง password

### A2 บรรทัด "ไม่เอา"

ก่อน:
> ไม่เอา: username + password, email + password เป็นทางหลัก, Facebook เป็นทางหลัก

หลัง (เสนอ · เปลี่ยนเล็กน้อยเพื่อไม่ให้อ่านว่าห้าม email ทั้งหมด):
> ไม่เอา: username + password, email + password เป็นทางหลัก (เป็นได้แค่ทางรอง), Facebook เป็นทางหลัก

### A3 แผนภาพ

ก่อน: `Auth Provider (Google / Apple)`
หลัง (เสนอ): `Auth Provider (Google / Apple · ทางรอง Email)`
ส่วนที่เหลือของแผนภาพ (Game Account → Player Profile → Class, Level/Stat, Equipment, Inventory, Progress) ไม่เปลี่ยน

### A4 ย่อหน้า PDPA (เติมหนึ่งประโยคท้าย)

ก่อน:
> ข้อควรระวังด้าน PDPA: social login พ่วงข้อมูลส่วนบุคคลจาก provider มาด้วย เก็บเท่าที่จำเป็น (provider id อย่างเดียวพอ) และอย่าดึงชื่อจริงหรืออีเมลมาแสดงใน profile ตามกฎที่ตั้งไว้ว่าไม่มีข้อมูลระบุตัวตนจริงในเกม

หลัง (เสนอ · เติมท้าย):
> … ตามกฎที่ตั้งไว้ว่าไม่มีข้อมูลระบุตัวตนจริงในเกม ทาง email เก็บอีเมลได้เฉพาะในระบบ auth เพื่อใช้เข้าสู่ระบบและรีเซ็ตรหัสเท่านั้น ไม่อยู่ใน player profile ไม่แสดงในเกม ไม่อยู่ใน telemetry และเกมไม่เก็บ password เอง (ใช้ระบบ auth ที่เก็บแบบ hash)

ย่อหน้า "ตัวละครผูกกับ account ไม่ใช่เครื่อง" ไม่เปลี่ยน

## 4. ส่วน B — "10 นาทีแรกของคนใหม่" แถวนาที 0–1 (D-146, D-147, D-149 · ข้อเสนอแยก)

D-145 สั่งร่างเฉพาะเรื่อง password แต่ตอนเขียน spec F10 พบว่าแถวนาที 0–1 ของ GDD ต่างจาก D-149 ด้วย: GDD ให้เห็นแผนที่ก่อนแล้วเลือกพลัง "เลือกเสร็จเข้าเกมเลย" · D-149 ให้ login, สร้างตัวละคร (พลัง + ชื่อ) และเรื่องเล่า 5 slide มาก่อนแผนที่ · คนสั่ง D-149 แล้ว (ACCEPTED) ข้อนี้จึงเป็นการทำ GDD ให้ตรงกับคำสั่ง ไม่ใช่คำถามใหม่ · คนเลือกได้ว่าจะรวมในรอบ Q-P2-10 หรือไม่

ก่อน:
> | นาที 0–1 | ขึ้นว่า "กรุงเทพฯ กำลังมีปัญหา" เห็นแผนที่และรอยแยกใกล้ตัว แล้วให้เลือกพลังทันที — Tanker, Ranged, Support, Magic เลือกเสร็จเข้าเกมเลย |

หลัง (เสนอ):
> | นาที 0–1 (ยืดได้ถึงราว 2) | กดเริ่มเกม เข้าสู่ระบบ ยืนยันอายุ ให้สิทธิ์ตำแหน่ง แล้วสร้างตัวละคร — เลือกพลัง Tanker, Ranged, Support, Magic ตั้งชื่อหรือกดสุ่ม เรื่องสั้นไม่เกิน 5 หน้าว่า "กรุงเทพฯ กำลังมีปัญหา" ข้ามได้ จบแล้วเห็นแผนที่และรอยแยกใกล้ตัวเลย |

เหตุผลของถ้อยคำ:
- "ข้ามได้" และ "ไม่เกิน 5 หน้า" รักษาหลักการของหัวข้อเดียวกัน ("อย่าให้อ่าน lore 20 หน้าแล้วค่อยเล่น") และรายการห้ามสอน "lore ยาวๆ" · backstory ของผู้เล่นใน "เรื่องเล่า" ยัง "ห้ามมีมากกว่านี้" ไม่ต้องแก้หัวข้อนั้น
- "ยืดได้ถึงราว 2" เป็นช่วงที่ขั้นเพิ่มน่าจะใช้ · ตัวเลขจริงวัดจาก funnel ของ PRD F10 (product-manager) · ถ้าคนไม่อยากให้ GDD มีตัวเลขนี้ ตัดวงเล็บออกได้โดยไม่เสียความหมาย
- ไม่มีส่วนใดเปลี่ยนนาที 1–10 หรือรายการ "สิ่งที่ห้ามสอนใน 10 นาทีแรกเด็ดขาด"
