### 2.1 เหตุผลของ PASS ราย role (หลักฐาน)

**systems-designer:** ทุกค่าอยู่ใน config มี `_source` หรือ `_assumption` (balance-model หัวข้อ 0) ตรง NN-3 · movement gate มีที่เดียว `dungeons.json#movementGate` ใช้กับ dungeon, raid และการปิดฉุกเฉิน ไม่มีทางลัด (หัวข้อ 9, NN-2) · drop, exp และรายได้คิด "ต่อ reward tick ที่ผ่าน movement gate เท่านั้น" (หัวข้อ 4.1, 7) · RNG และการปัดเศษจำนวน Common ทำฝั่ง server (A-22, NN-1) · ตีบวก `itemCanBreak = false`, `itemCanBeDestroyed = false` (หัวข้อ 6, NN-6) · auto-retreat 25% เปิด default คู่ movement gate (หัวข้อ 9, NN-8) · ไม่มีการ "แก้เงียบ": ค่าเดียวที่เปลี่ยนคือ hit chance 50 → 54 ซึ่งเป็นค่าสมมติ ไม่ใช่ค่า GDD และบันทึกเป็น D-029 · ข้อที่ขัด GDD ทุกข้อถูกส่งเป็น decision (D-020, D-021, D-030, D-038, D-039) แทนการปรับเอง · ลำดับปลดตรง D-041 และร้าน NPC ตาม D-065 (หัวข้อ 10)

**art-director:** style guide V1 "อ่านออกกลางแดดก่อนสวย" (AA ขั้นต่ำ เป้า 7:1, ทดสอบจอจริงกลางแดด S10) ตรง P4 และข้อจำกัด GDD เรื่องแดด · V3 "น่ารักแบบ isometric ก้อนกลม" 2D dimetric 2:1 ห้าม voxel และ 3D render ตรง GDD "Avatar" และรายการตัด v1 (avatar 3D) · V4 และหัวข้อ 8.2 ห้ามศาสนา สถาบัน การเมือง แบรนด์จริง ตรง P5 · หัวข้อ 9.1 ตีบวกเป็นตู้จ่ายบิล ไม่มีภาพของแตก ไม่มีประกายแบบพนัน ตรง NN-6 และ GDD "ระบบตีบวก" · icon grammar ให้ rarity อ่านได้ 4 ช่องทางโดยไม่พึ่งสีหรือ motion · map-style: dungeon แสดงแค่จำนวนคนและ role ระดับ dungeon (`label_count`) ผ่าน whitelist 6 property ห้าม spread payload ของ server ไม่มี heatmap และไม่มี layer ที่วาดซ้ำตามเวลา (หัวข้อ 6, 11) ตรง NN-4 และ P4 · avatar-spec หัวข้อ 1 และ 11: โครงตัวเดียวไม่ระบุเพศ ไม่แสดง rarity/tier/ระดับตีบวก

**vfx-animator:** ทุก effect เป็น finite one-shot หยุดทันทีเมื่อ `visibilitychange` มี reduced-motion ทุกตัว ไม่มี motion บนแผนที่ (หัวข้อ 1–2, 8) ตรง P4 · motion ไม่เคยเป็นช่องทางเดียวของข้อมูล (หลักข้อ 2) · auto-retreat เป็น "ถูกดึงออกอย่างสุภาพ" ห้าม shake, vignette แดง, slow-motion (6.2) · ตายเป็น HP ตัดลง 0 ทันทีแล้ว grayscale ไม่มี "GAME OVER" (6.3) ตรงโทนแห้งของ P5 และถ้อยคำ GDD ในสามจังหวะ · auto-retreat เปลี่ยนหน้าจอ ส่วนตายอยู่จอเดิม ทำให้แยกสองเหตุการณ์ได้แม้ไม่อ่านข้อความ · ตีบวกสำเร็จและล้มเหลวใช้ motion เดียวกัน ของไม่สั่น ไม่ร้าว ไม่มี anticipation ก่อนเฉลย (หัวข้อ 7) ตรง NN-6 และไม่กระตุ้นแบบพนัน · HP bar tween เฉพาะไปยังค่าที่ server ส่งแล้ว ไม่เดาค่า (หัวข้อ 3) และผลตีบวก/drop แสดงทันทีที่ server รู้ผล จึงไม่มีตรรกะรางวัลฝั่ง client (NN-1) · quick command 10 ตัวเล่นที่การ์ด party ไม่ใช่บนแผนที่ (หัวข้อ 5, NN-4)

**product-manager:** north star = นาทีเดินที่ผ่าน movement gate ต่อผู้เล่น active คำนวณที่ server ไม่นับเวลาที่บ้าน (metrics หัวข้อ 1) ตรงเป้าหมายเดียวของเกมและ P1 · funnel นาที 0–10 ตรงตาราง "10 นาทีแรก" · guardrail ครอบ Economy (F-16), Progression (F-17, เลเวล 50+ หายหลังสัปดาห์ 4 ตาม GDD "เป้าหมายปลายทาง"), Places (death rate, รายงานซ้ำ), Seasonality (ฝน ไม่แก้ด้วยการผ่อน gate ตาม NN-8) · telemetry ห้ามพิกัดทุก event, `account_id` เป็น opaque, ไม่มี device id, ระยะส่งเป็น band, party ส่งแค่จำนวนและ role, รายงานเป็นหมวดไม่ใช่ข้อความอิสระ (telemetry หัวข้อ 1, 3, 4) ตรง NN-4 และ NN-7 · ความเสี่ยงของตัวเลข (screen lock, free tier) เขียนไว้ตรงไปตรงมา · ส่วนที่ขาดเป็นตัววัดของคำตัดสินใหม่ใน gate นี้ ไม่ใช่การขัด pillar (B-06, B-07)

### 4.1 D-039 นิยาม "คนเดียว" ในเป้า party 1.8–2.2 — ACCEPT

### 4.3 D-061 พัก dungeon จากรายงานผู้เล่น — CHANGE

ข้อเสนอเดิม: ผู้เล่นต่างกัน 5 คนภายใน 24 ชม. รายงานหมวดใดก็ได้ → พัก dungeon รอ moderator

ปัญหา: party หนึ่งมีได้ถึง 8 คน (`classes.json` เพดานสมาชิก) party เดียวจึงพัก dungeon ใดก็ได้ ซึ่งขัดกับเหตุผลใน `_assumption` ของ config เอง ("one small party cannot close a dungeon") และการพักผิดทำให้คนที่เดินทางมาเล่นไม่ได้ · ในทางกลับกัน GDD "คิวรายงานจากผู้เล่น" มีสามหมวด ("เข้าไม่ได้" "ที่นี่อันตราย" "ปิดถาวร") ซึ่งมีแค่หมวดอันตรายที่ต้องการการปิดเร็ว

คำตัดสิน (กฎที่ systems-designer ใส่ใน `dungeons.safety`)
1. การพักอัตโนมัติ (`suspendPendingModerator`) นับเฉพาะรายงานหมวดความปลอดภัย ("ที่นี่อันตราย") · หมวด "เข้าไม่ได้" และ "ปิดถาวร" เข้าคิว moderator พร้อมสถิติรายงานซ้ำตาม GDD ไม่พักอัตโนมัติ
2. รายงานที่นับต้องมาจากผู้เล่นที่อยู่ที่ dungeon นั้นจริงภายในหน้าต่างเวลา (check-in ผ่านหรือมี run ที่ dungeon นั้น) และ trust score ไม่ต่ำ · server ตัดสิน ไม่เปิดเผยตัวผู้รายงาน
3. ต้องมาจากอย่างน้อย 2 กลุ่มที่ไม่ใช่ party เดียวกัน ณ ตอนรายงาน (คนเล่นคนเดียวนับเป็นหนึ่งกลุ่ม) · ค่าเกณฑ์จำนวนคน หน้าต่างเวลา และจำนวนกลุ่มขั้นต่ำเป็น config (ค่าตั้งต้น 5 คน / 24 ชม. คงเดิม)
4. moderator ได้แจ้งเตือนทันทีที่ถึงเกณฑ์ · dungeon กลับมาเปิดได้โดย moderator เท่านั้น · ผู้เล่นข้างในได้รางวัลตามกฎปิดฉุกเฉิน (D-059)
5. หน้ารายงานเป็นหมวดให้เลือกเท่านั้น ไม่มีช่องพิมพ์ (NN-4)

หลักการ: ข้อ 3 (กันการพักผิดที่ทำให้คนเดินทางมาแล้วเล่นไม่ได้) โดยยังคงการปิดเร็วสำหรับอันตรายจริงตาม GDD "ความปลอดภัยทางกายภาพ" · ข้อ 2 ใช้ในข้อ 2 ของคำตัดสิน (สิทธิ์ส่งผลต่อโลกเกมผูกกับการไปถึงที่จริง) · B-02

### 4.4 D-056 ร่างอวตารฐานเดียว ไม่มี field เพศ — ACCEPT

- ตรง GDD "Avatar": 2D layered และ "เพิ่มไอเทมใหม่คือวาดภาพเดียว" · ร่างที่สองทำให้งานวาดทุกไอเทมเพิ่มเท่าตัว ซึ่งขัดเหตุผลที่ GDD เลือก 2D ตั้งแต่ต้น

- ร่างที่สองเป็นเรื่องงบของ HUMAN ในอนาคต ไม่ใช่ v1
- หลักการ: ข้อ 1 (คนขยันได้ของ แต่ไม่ต้องมีเวทีอวด) และ NN-7 · A-P1-F03-T11-2 ใน avatar-spec ถือว่ายืนยันแล้ว

### 4.5 F-12b ยาฟื้นเกินที่ว่างของ HP — ทิศทาง (งานตัวเลขอยู่ Phase 4)

ข้อเท็จจริง (sim-report 5.3): ยาอัตโนมัติใช้ที่ 40% จึงมีที่ว่างให้ฟื้นได้ 60% · VIT ของ build สมดุลทำให้ยาเล็ก (30%) ฟื้นได้ 62% ที่เลเวล 25 และราว 100% ที่เลเวล 60 · ยากลางและใหญ่ฟื้นเกินที่ว่างทุกกรณี ส่วนเกินหายไป ยาเล็กจึงดีสุดเสมอ และลำดับราคา 150 / 400 / 1,000 ไม่มีเหตุผลให้ซื้อขวดใหญ่

การวินิจฉัย: การที่ยาเล็กคุ้มสุดต่อ 1% HP เป็นเจตนาอยู่แล้ว (balance-model 8.1: ยาใหญ่จ่ายเพื่อความเร็ว) ปัญหาจริงมีสองข้อ (1) ในเกม idle ที่ยาอัตโนมัติทำงานแทน "ความเร็ว" ไม่มีค่า (2) VIT ทำให้ส่วนเกินโตตามเลเวลจนยาเล็กเองก็เริ่มสูญ

ทิศทาง
1. **บทบาทของขนาดยา = ยั่งยืน vs ฉุกเฉิน ไม่ใช่ความคุ้มต่อ HP:** ยาเล็กคือยาของยาอัตโนมัติในการเดินปกติ · ยากลางและใหญ่มีไว้สำหรับจังหวะที่ damage ครั้งเดียวมากกว่าที่ยาเล็กเอาคืนได้ (เข้า dungeon ต่ำกว่าช่วงเลเวล, สัปดาห์หลังล้มบอสไม่สำเร็จ, raid) และการกดใช้เองก่อนเข้า run · ไม่ต้องทำให้ขวดใหญ่ "คุ้ม" ในการเดินปกติ
2. **กฎเลือกยาของยาอัตโนมัติ (ส่งเป็นงาน Phase 4):** ใช้ยาที่เล็กที่สุดที่พา HP กลับขึ้นเหนือเกณฑ์ยาอัตโนมัติได้ในครั้งเดียว ถ้ายาเล็กไม่พอ (เช่น โดนตีครั้งใหญ่) ค่อยขยับขนาด · ผู้เล่นตั้งลำดับยาและเกณฑ์เองได้ในหน้าตั้งค่า (GDD "ใช้ยาเองเมื่อ HP ต่ำกว่าเกณฑ์ที่ตั้ง") · server เป็นผู้เลือก ไม่ใช่ client
3. **ส่วนเกินจาก VIT แก้ด้วยคันโยกเดียวกับ D-038:** ถ้า HUMAN เลือกทางเลือก B (+1% ต่อแต้ม) ยาเล็กที่เลเวล 60 (VIT ราว 116) ฟื้นราว 65% ส่วนเกินเหลือราว 5% ปัญหาหายเกือบหมดโดยไม่ต้องมีกฎใหม่ · ถ้าเลือก A ให้ Phase 4 เสนอเพดานโบนัสประสิทธิภาพยาจาก VIT เป็น config key แยก (ต้องเป็น decision HUMAN เพราะกระทบตาราง Stat ของ GDD ที่เลเวลสูง)
4. ไม่แก้ราคายาหรือ % ของยาใน Phase 1 · ราคาและขนาดยายังเป็นค่า GDD

หลักการ: ข้อ 1 (ยาเป็น gold sink หลัก ถ้าส่วนเกินทำให้ gold sink หายไปเงียบๆ เศรษฐกิจรั่ว) แล้วข้อ 3 (ไม่ขึ้นราคายาให้คนที่ไม่ลง VIT) · B-05

### 4.6 กฎ R-B1 ลำดับการคิดต่อการโดนตีหนึ่งครั้ง (game rule ใหม่ จาก A-P1-F03-T07-2)

ที่มา: GDD "ระบบกันตาย" และ "พอมี auto-retreat แล้ว การตายจะเกิดเฉพาะกับคนที่ตั้งใจเสี่ยงหรือปิด auto ไว้เอง" · balance-model 3.1 ยังไม่ระบุลำดับ และ `product/telemetry-events.md` (`run_death`) เขียนว่าตายได้เมื่อ "HP ลดเร็วกว่าระบบดึงทัน" ซึ่งขัดกับประโยค GDD นี้

ลำดับที่ server ใช้ทุกครั้งที่ผลทอยว่าโดนตี
1. คิด damage ตามสูตร (หัวข้อ 3.1) · โล่ Magic ดูดซับก่อน
2. ถ้าเปิด auto-retreat อยู่: HP หลังหักต่ำสุดเป็น 1 (การโดนตีครั้งเดียวทำให้ตายไม่ได้) · ถ้าปิด auto-retreat: HP ลงถึง 0 ได้ และ HP 0 = ตายทันที ยาอัตโนมัติไม่ชุบ (ชุบใช้ยาชุบชีวิตหรือ Support ตามปกติ)
3. ถ้า HP < เกณฑ์ยาอัตโนมัติ (`config: economy.autoPotion.defaultThreshold_pct` หรือค่าที่ผู้เล่นตั้ง) และมียา: ใช้ยาตามกฎเลือกยา (4.5 ข้อ 2)
4. ถ้าเปิด auto-retreat และ HP หลังใช้ยา ≤ `config: dungeons.hpSafety.autoRetreatThreshold_pct`: ถอนอัตโนมัติ ของเก็บครบ run จบ
5. แจ้งเตือน HP ต่ำ (`config: dungeons.hpSafety.lowHpWarningThreshold_pct`) ประเมินจาก HP สุดท้ายของลำดับนี้ ยิงครั้งเดียวต่อการลงผ่านเกณฑ์ · ถ้าข้อ 4 เกิดในครั้งเดียวกัน ให้ auto-retreat เป็นสัญญาณเดียว (ตาม priority ของ `audio/cue-list.md`)

ผล: เปิด auto-retreat (default) = ไม่มีทางตายจากมอนสเตอร์ · ยาในกระเป๋าถูกใช้ก่อนพาออก · ปิด auto-retreat = รับความเสี่ยงเองตาม GDD
หลักการ: ข้อ 3 และ NN-6/NN-8 (auto-retreat เป็นครึ่งหนึ่งของกฎคู่ ต้องกันตายได้จริง ไม่ใช่ "ส่วนใหญ่") · B-03, B-06

## 5. คำแนะนำต่อ decision ของ HUMAN และยืนยันค่า config

gate นี้ไม่ตัดสินแทนคน ข้อ 5.1 และ 5.2 เป็นความเห็นของ game-director สำหรับ HUMAN P1-F03-T28 (SF-1)

### 5.1 D-020 เวลาอยู่รอด 45 นาที (27.8 นาทีของคนเดียวที่ไม่ใช่ Tanker)

คำแนะนำ: **ยอมรับนิยามของ D-020 และยอมรับ 27.8 นาทีใน v1 โดยไม่แก้ debuff ขาด Tanker ×1.6 พร้อมตัวชี้วัดเฝ้าดูและคันโยกที่เตรียมไว้**
- นิยาม "อยู่รอด = เวลาถึงตอนถูกพาออก (auto-retreat 25%) ที่ damage ×1.0" ตรงกับประสบการณ์ผู้เล่น เพราะเมื่อ auto-retreat เปิดเป็น default HP 0 เกิดไม่ได้ (กฎ R-B1) เวลาถึง HP 0 จึงไม่ใช่สิ่งที่ผู้เล่นรู้สึก (ความเห็นเดิมใน SF-4)
- 27.8 นาทีไม่ใช่ "นั่งรถเมล์มา 40 นาที เกมฆ่าใน 5 นาที" ตามที่ GDD ห้าม: (ก) ถูกพาออกพร้อมของครบ ไม่มีการเสียของ (ข) หลัง run แรกร้าน NPC เปิดและยาอัตโนมัติยืดเวลาเล่นได้ไม่จำกัด โดยอัตราส่วนรายได้ต่อค่ายาของคนเดียวทุก class ยังมากกว่า 1 (1.27–4.53, sim-report 5.2) คือเดินต่อได้โดย gold ไม่ติดลบ (ค) run แรกของคนใหม่ยังยาวเกิน 10 นาทีแรกเกือบสามเท่า
- ความต่างระหว่าง Tanker คนเดียว (55.6 นาที) กับ class อื่น (27.8) เป็นเหตุผลให้หา party โดยไม่บังคับ (หลักการข้อ 4, 5)
- สิ่งที่ต้องเฝ้า: เวลาใน run ถึง auto-retreat แยก class และขนาด party (B-06) · คันโยกที่เตรียมไว้: ถ้าหลัง beta ค่ามัธยฐานของ run คนเดียวที่ไม่ใช่ Tanker ที่จบด้วย auto-retreat ต่ำกว่าราว 20 นาที ให้ systems-designer ลด `classes.json` debuff ขาด Tanker จาก 1.6 ไม่เกิน −20% (ถึง 1.3) ซึ่งอยู่ในอำนาจของ systems-designer
- หลักการ: ข้อ 3 แล้วข้อ 4
- ถ้า HUMAN ไม่รับนิยาม: ต้อง fit hit chance ใหม่ให้แถว 45 นาทีรวม ×1.6 ผลคือกรณีมี Tanker ยาวเกิน GDD มาก (ราว 92 นาที, F-1) และค่ายาทุกตัวใน sim-report เปลี่ยน

### 5.2 D-038 เป้ารายได้ต่อค่ายาวัดที่ใครและใช้คันโยกอะไร

คำแนะนำ: **ทางเลือก B** (ประสิทธิภาพยาจาก VIT +2% → +1% ต่อแต้ม และวัดเป้าที่ "คนเดียวเฉลี่ย 4 class, VIT on, เลเวล 25" โดยกรณีอ้างอิงของ GDD ยังเป็น vector รอง)
- หลักการข้อ 1 มาก่อน: ทางเลือก A ปล่อยให้คนเดียวที่ลง VIT ได้อัตราส่วน 3.6–4.2 ซึ่งเกินเป้า 3 คือ gold ไหลเข้าเศรษฐกิจมากกว่าที่ GDD ตั้งใจ · B ดึงเลเวล 25 กลับเป็น 2.69 และกรณีอ้างอิง GDD ยัง 2.83
- หลักการข้อ 3: B ไม่ขึ้นราคายา คนที่ไม่ลง VIT จ่ายเท่าเดิม ส่วน D และ E ขึ้นราคาทุกคนและดันกรณีอ้างอิงต่ำกว่า 2.45
- ผลพลอยได้: B แก้ F-12b เกือบทั้งหมด (4.5 ข้อ 3)
- ข้อจำกัดที่ HUMAN ควรรู้: B ต้องแก้ตาราง Stat ใน GDD (−50% ของค่า GDD) · เลเวล 40–60 ยังเกิน 3 · คนเดียว Support/Magic ที่ไม่ลง VIT ยังราว 1.3 (ยังบวก) · party ครบ role แทบไม่ซื้อยา (F-13/F-16) ไม่มีทางเลือกใดแก้ ถือเป็นคุณค่าของ party ตามหลักการข้อ 4 และเฝ้าด้วย GR-5
- ถ้า HUMAN ไม่ต้องการแก้ GDD: ทางเลือก A พร้อมให้ liveops วัดอัตราส่วนจริงแยก class หลัง beta และ Phase 4 ทบทวนตัวคูณ VIT ของรองเท้า (A-6) กับเพดานโบนัสยา (4.5 ข้อ 3)
