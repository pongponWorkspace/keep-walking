## 2. Flow A — Onboarding นาที 0–10 (F06-R36..R43, ตาราง 3.8 ของสเปก)

state machine อ้างอิง (สเปกหัวข้อ 4): `O-intro` → `O-age` → (`O-underage` จบ) / `O-consent` → `O-permission` → `O-map` → `O-class` → `O-nearest` (ใกล้) หรือ `O-home` (ไกล/นอกพื้นที่/ไม่รู้ตำแหน่ง) → `O-first-run` → `O-done` — เก็บใน `kw.p2.*` เป็นขั้นที่ผ่านแล้ว เปิดแอปใหม่กลางทางกลับไปขั้นแรกที่ยังไม่ผ่าน (F06-R36, H-E18)

A1. **`S-00-intro`** — ข้อความเดียว `[onboarding.intro]` ("กรุงเทพฯ กำลังมีปัญหา") ไม่มีปุ่มข้าม กดที่ใดก็ได้ทั้งจอเพื่อไปต่อ (ปุ่มเดียวเต็มจอ) → `S-00-age-gate` (**ไม่ใช่ consent ตำแหน่งตามที่ F03 เขียนไว้เดิม — ดูหมายเหตุ override ข้อ 1**)

A2. **`S-00-age-gate`** — หัวจอ `[age.gateTitle]` ("ยืนยันอายุ") + `[age.gateBody]` ("เกมนี้สำหรับอายุ {minAge} ปีขึ้นไป เลือกปีเกิดแล้วกดยืนยัน") ตัวเลือกปีเกิดจากรายการ `[age.gateOptions]` (ไม่พิมพ์) + ปุ่มยืนยันแยก `[age.gateConfirm]` (`.btn-disabled` จนกว่าจะเลือกตัวเลือก) — เกณฑ์ผ่าน/ไม่ผ่านคำนวณจาก `config: privacy.minAge_yr` แบบ `minAgeComparison` เก็บในเครื่องเฉพาะธง "ผ่านแล้ว" ไม่เก็บปีเกิดหรือช่วงอายุ (F06-R45)
   ⤷ เงื่อนไข: ผ่านเกณฑ์ → `S-00-consent-location`
   ⤷ เงื่อนไข: ต่ำกว่าเกณฑ์ (หลังกดยืนยัน) → `S-00-underage` (`O-underage`, จบ flow): `[age.underMinTitle]` ("ยังเล่นไม่ได้ตอนนี้") + `[age.underMinBody]` (scaffold `config: unlocks.parentalConsent.enabled` ปิด — ไม่มีฟอร์ม ไม่เก็บข้อมูลใด ไม่ขอตำแหน่ง) ปุ่มเดียว `[age.underMinBack]` ("กลับหน้าแรก") กลับ `S-00-intro` **ไม่ไปต่อ flow onboarding ที่เหลือ** (F06-R46)

A3. **`S-00-consent-location`** — หัวจอ `[consent.locationTitle]` ("ขอใช้ตำแหน่งของคุณ") เนื้อหา `[consent.locationBody]` (วัตถุประสงค์ + TTL `{ttlText}` จาก `config: privacy.positionLogTtl_s` + ไม่เปิดเผยผู้เล่นอื่น + ถอนได้ทุกเมื่อ) ปุ่มคู่น้ำหนักเท่ากัน `[consent.locationAccept]` ("อนุญาต") / `[consent.locationDecline]` ("ไม่อนุญาต") — เป็นจอ consent แยกจอเดียว ไม่รวมกับ consent อื่น (Phase 2 ไม่มี consent อื่นในแอปเพราะไม่มีข้อมูลออกจากเครื่อง, F06-R47)
   ⤷ เงื่อนไข: อนุญาต → `S-00-permission-browser`
   ⤷ เงื่อนไข: ไม่อนุญาต → ข้าม `S-00-permission-browser` ไปที่ `S-01-map` ตรงสถานะ **ไม่รู้ตำแหน่ง** ทันที (F06-R48) — ยังเลือกพลังได้ต่อ (A6) onboarding ไม่ติดค้าง

A4. **`S-00-permission-browser`** — หัวจอ `[consent.browserPrimingTitle]` ("อีกขั้นเดียว") + `[consent.browserPrimingBody]` ("เดี๋ยวเครื่องจะเด้งถามซ้ำอีกรอบ กดอนุญาตอีกทีก็จบ") ปุ่มเดียว `[consent.browserPrimingContinue]` ("ไปต่อ") → trigger native geolocation prompt ของเบราว์เซอร์/OS (ไม่ใช่ UI ของเกม)
   ⤷ เงื่อนไข: อนุญาตจริงจาก OS → `S-01-map` สถานะตามตำแหน่งจริง (ใกล้/ไกล/นอกพื้นที่)
   ⤷ เงื่อนไข: ปฏิเสธจาก OS (ต่างจากปฏิเสธ consent ในเกมที่ A3) → `S-01-map` สถานะไม่รู้ตำแหน่ง เหมือน A3 ปฏิเสธ

A5. **`S-01-map`** (`O-map`) — แผนที่จริงปรากฏครั้งแรก สถานะใดก็ได้ตามตำแหน่งจริง (ใกล้/ไกล/นอกพื้นที่/ไม่รู้ตำแหน่ง) → ทันทีที่ถึงจอนี้ เปิด `S-00-class-select` sheet ทับแผนที่ (A6) **ไม่ต้องรอผู้เล่นทำอะไรก่อน** (แผนที่มาก่อนเลือกพลัง ตาม F-05 ของ ia.md แต่ sheet ทับขึ้นทันทีในเฟรมถัดไป ไม่ใช่ให้ผู้เล่นเลื่อนดูแผนที่ก่อน)

A6. **`S-00-class-select`** (`O-class`) — drawer sheet ทับ `S-01-map` (ไม่ใช่หน้าเต็มจอแยก) รายละเอียดเต็มอยู่หัวข้อ 3 ของเอกสารนี้ (Flow B) — สรุปที่นี่แค่ตำแหน่งใน onboarding: เลือก 1 ใน 4 แบบ → ปิด sheet เข้าเกมทันที (ไม่มีหน้ายืนยันซ้อน) → กลับเห็นแผนที่เดิมที่สถานะไม่เปลี่ยน ปิดนาที 0–1 (F06-R29)
   ⤷ เงื่อนไข: ปิดแอปก่อนเลือก (H-E18) → เปิดใหม่ sheet ขึ้นทับแผนที่อีกครั้งทันที (บังคับเลือกก่อนเข้าเกม, F06-R29 "ข้ามไม่ได้")

A7. **สถานะหลังเลือกพลัง**:
   ⤷ เงื่อนไข: สถานะ **ใกล้** (มี dungeon ที่เปิดอยู่ในเกณฑ์ `config: unlocks.home.farDungeonThreshold_m` ที่ช่วงเลเวลครอบเลเวล 1) → `O-nearest`: เห็นการ์ดแนะนำตาม flow F04 หัวข้อ 2 (A2) ทันที — ระยะเส้นตรง+ทิศ+ปุ่มนำทาง (F06-R37: การ์ดแนะนำเลือกเฉพาะแห่งที่ **เปิดอยู่** เท่านั้น ห้ามแนะนำแห่งที่ปิด)
   ⤷ เงื่อนไข: สถานะ **ไกล / นอกย่านเปิดตัว / นอกพื้นที่ / ไม่รู้ตำแหน่ง** → `O-home`: ไปจอที่บ้านตามสถานะจริง (รายละเอียดเต็มอยู่หัวข้อ 7 ของเอกสารนี้ Flow F) sheet เลือกพลังขึ้นทับจอที่บ้านเหมือนกันทุกประการ (F06-R52 ยืนยันชัดกรณีนี้) — onboarding ค้างที่ `O-home` จนผู้เล่นเดินเข้าใกล้ในภายหลังแล้วสถานะกลับเป็นใกล้ จึงกลับเข้า `O-nearest` ต่อ (ไม่เริ่ม onboarding ใหม่ตั้งแต่ต้น เพราะเลือกพลังทำไปแล้ว) **ไม่มีทางลัดหรือเกณฑ์ผ่อนสำหรับกรณีนี้** (ไม่ใช่ทางแก้ฝนตกเต็มรูป — pillars 7: "ทำให้อยากออกไปเดิน ไม่ใช่ทดแทนการเดิน")

A8. **`S-02-dungeon-confirm`** — รายละเอียดเต็มอยู่ flow F04 หัวข้อ 3–4 (popup เดียวกันทุกครั้ง ไม่ว่า onboarding หรือเล่นมานาน) เอกสารนี้เติมแค่ส่วนของ F06: ถ้า HP ปัจจุบัน ≤ `config: dungeons.hpSafety.autoRetreatThreshold_pct` และเปิด auto-retreat อยู่ ใต้ช่วงเลเวลมีบรรทัดเพิ่ม `[dungeon.confirmLowHpNote]` ("HP แค่นี้ โดนตีทีเดียวระบบพากลับเลย" — แซะ ไม่ขู่ ไม่บล็อกการเข้า, F06-R05) — **onboarding รอบแรกของบัญชีใหม่ HP เต็มเสมอเพราะยังไม่เคยโดนตี บรรทัดนี้จึงไม่ปรากฏในรอบแรกจริง** แต่ flow ต้องรองรับไว้เพราะ run ที่สองเป็นต้นไปอาจเข้าเงื่อนไขนี้ · ถ้าปิด auto-retreat อยู่ (ไม่เกิดขึ้นได้ในรอบแรกเพราะปิดต้องเข้าไปตั้งค่าเอง) ใช้ป้าย `[run.autoRetreatOffBadge]` แทน ไม่ใช่บรรทัดนี้

A9. **เข้า run ทุกครั้งที่ยังไม่มีธง `first_reward` (แก้ B-02)** — `S-03-run` แสดง `[dungeon.confirmTutorialLine]` ("เดินต่อไปเพื่อรับรางวัล") ทับสั้นๆ **เป็น tutorial บรรทัดเดียวของทั้งเกม** เงื่อนไขแสดงคือ **"ยังไม่มีธง `first_reward` ใน onboarding state (F06-R36/R38)" ไม่ใช่ "run แรก"** — ผู้เล่นที่ run แรกออกก่อนครบ tick หรือ tick แรกไม่ผ่าน gate (H-E20) ยังไม่ได้ธงนี้ จึงเห็นบรรทัดเดิมอีกใน run ถัดไปซ้ำได้หลายครั้งจนกว่าจะได้รางวัลก้อนแรกจริง (A11) แล้วจึงไม่แสดงอีกตลอดไป แสดงก่อนสลับเข้าจอพกกระเป๋า (หรือทับบนจอพกกระเป๋าถ้า Wake Lock ใช้ได้และสลับเร็ว — รายละเอียดจังหวะเต็มอยู่หัวข้อ 6 ของเอกสารนี้ Flow E) ไม่มี tooltip อธิบาย HP bar หรือ tick timer เพิ่มเติมใดๆ (F06-R38, N-3 ของ F04-flow-approval) [handoff narrative: แก้ context ของ `dungeon.confirmTutorialLine` จาก "ครั้งเดียวในชีวิตผู้เล่น" เป็น "ทุก run จนกว่าจะมีธง first_reward" — N-05]

A10. **นาที 6–8 (party) ข้ามทั้งช่วงใน Phase 2** — ไม่มีแผงว่างใดๆ ให้เห็น (Phase 2 ไม่มี Nearby Party ตาม `design/features/F04-dungeon-presence.md` หัวข้อ 6) ไม่ต้องมีจอรองรับ

A11. **รางวัลก้อนแรก (นาที 8–10)** — รายละเอียดเต็มอยู่ flow F05 หัวข้อ 2 (Flow A ข้อ A2): tick ปกติที่ผ่าน gate ครั้งแรกในชีวิตผู้เล่น ใช้ `[run.tickGrantedFirst]` + effect เด่นกว่า ตามด้วย `[run.continueCta]` — **onboarding จบที่จังหวะนี้ (`O-done`) แม้ run นั้นจะจบด้วย `death` ภายหลัง** (F06-R40) ไม่มีจอสรุป onboarding แยก ไม่มี badge ไม่มีของแถมพิเศษ (F06-R39, D-089) ผู้เล่นเข้าสู่ core loop ปกติทันที
   ⤷ เงื่อนไข: tick แรกไม่ผ่าน gate (H-E20) → `[run.tickDenied]` ตามปกติ (flow F05 A3) **ไม่มีทางลัดของ onboarding** รอ tick ถัดไป — เกิดขึ้นได้และไม่ใช่บั๊ก

## 3. Flow B — เลือก class (sheet บนแผนที่) และหน้าอ่าน role (F06-R29..R32)

B1. **`S-00-class-select`** — drawer sheet (`.drawer` ตาม style.css) ทับ `S-01-map` หรือทับจอที่บ้าน (Flow F) แล้วแต่สถานะ หัวจอ `[onboarding.pickRoleTitle]` ("เลือกพลัง") + คำใบ้ `[onboarding.pickRoleHint]` ("เลือกเสร็จเข้าเกมเลย") — การ์ด 4 ใบเรียงแนวตั้งหรือ grid 2×2 (ตามพื้นที่จอ) แต่ละใบ: `.class-badge` สี `class.tanker`/`ranged`/`support`/`magic` + ชื่อ (`class.tanker` ฯลฯ) + ผลหนึ่งบรรทัดไม่มีตัวเลข (`onboarding.pickRoleTanker/Ranged/Support/Magic`) — **ไม่มีค่าที่เลือกไว้ล่วงหน้า** ต้องแตะเลือกเอง (F06-R29) แตะการ์ดใดการ์ดหนึ่ง → ปิด sheet ทันที **ไม่มีปุ่มยืนยันแยก ไม่มีหน้ายืนยันซ้อน** (ต่างจากรูปแบบ popup ทั่วไปของเกมโดยตั้งใจ เพราะการเลือกนี้เปลี่ยนไม่ได้จนกว่าจะปลด U5 — F06-R30 — การไม่มีปุ่มยืนยันซ้อนไม่ได้แปลว่าตัดสินใจง่ายเกินไป เพราะการ์ดใหญ่พออ่านได้ในแวบเดียวและ sheet ไม่ปิดเองจนกว่าจะแตะ)

B2. **เข้าถึงได้ทุกเมื่อหลังเลือกแล้ว**: `S-05-role-info` (`[roleInfo.title]` "แต่ละพลังทำอะไร") ใช้คำอธิบายเดียวกับการ์ดของ B1 (`onboarding.pickRole*`) จับคู่ชื่อจาก `class.*` — เข้าถึงได้จากทุกสถานะที่บ้าน (Flow F) และจาก `S-10-profile` **ไม่มีทางไปหน้านี้จากในจอ run** (ไม่ใช่ระบบที่ต้องอ่านระหว่างเดิน)

B3. **ห้ามอธิบาย stacking หรือ debuff ของ party ที่ใดเลย** (F06-R32, U6) — คำอธิบายทั้งของ B1 และ B2 เป็นระดับ "ผลตอนเล่นคนเดียว" อย่างเดียว (เช่น Tanker "ทั้งทีมโดนตีเบาลง" เป็นคำอธิบายทั่วไปของ role ไม่ใช่สูตร buff/debuff ของ party จริง) ไม่มีตัวเลข % ไม่มีคำว่า "ขาด Tanker" หรือ "missingDebuffMult" ที่ใดในถ้อยคำที่ผู้เล่นเห็น

B4. **Phase 2 เปลี่ยน class ไม่ได้** (F06-R30, U5) — ไม่มีปุ่มหรือลิงก์ใดจาก `S-05-role-info`, `S-10-profile` หรือที่ใดไปหน้าเปลี่ยน class ทางเดียวคือลบข้อมูลในเครื่อง (หัวข้อ 8 ของเอกสารนี้) แล้วเลือกใหม่ตอน onboarding รอบใหม่

## 4. Flow C — HP, การตี, แจ้ง 30%, auto-retreat, ตาย, ฟื้น (F06-R01..R28, R-B1)

ที่มา: การตีเป็นการคำนวณล้วนของ engine (`resolveHit`, ไม่มี combat log ให้ผู้เล่นเห็น) — จอผู้เล่นแสดงแค่ **ผล** ของลำดับ R-B1 (flow F05 หัวข้อ 2 A5 ยืนยันลำดับ tick ก่อน hit อีกครั้ง) ไม่มีจอ "กำลังต่อสู้" ใดๆ ทั้งสิ้น

### 4.1 HP bar (ถาวรบน `S-03-run` ทุกสถานะ รวมจอพกกระเป๋า)

C1. HP bar (`.hp-track`/`.hp-fill` เดิมจาก style.css + เส้นแบ่งขอบ `components.md` 13.6) แสดงค่าจาก engine เท่านั้น (client ห้ามคำนวณเอง, F06-R11) ต่อเนื่องข้าม run (F06-R02) — **onboarding รอบแรกไม่มี tooltip อธิบาย HP bar** (F06-R41, ตรงกับ N-3 ของ F04-flow-approval — บทเรียนเดียวคือ `dungeon.confirmTutorialLine` เท่านั้น)

C2. **แจ้ง HP ต่ำ (H1, F06-R14)**: HP ก่อน hit > `config: dungeons.hpSafety.lowHpWarningThreshold_pct` และ HP สุดท้ายหลังยา ≤ เส้นนั้น → สั่น (ถ้าเครื่องรองรับ) + เสียง + toast `[run.hpLow]` ("HP ต่ำ กลับบ้าน ซื้อยา หาเพื่อนที่มี Support หรือไม่ก็เลิกดื้อ" — ข้อความ canon ตรงตัวห้ามแก้) ครั้งเดียวต่อการลงผ่านเส้น ติดอาวุธใหม่เมื่อ HP ขึ้นเหนือเส้นอีกครั้ง (ยา, Support heal) **ไม่แจ้งตอนเข้า run ที่ HP ต่ำกว่าเส้นอยู่แล้ว** (บอกไว้แล้วที่ popup confirm A8/`dungeon.confirmLowHpNote`) **ไม่แจ้งตอนตาย** (ลำดับ R14 ก่อน R23 เสมอ hit ที่พา HP ถึง 0 ไม่ทริกเกอร์บรรทัดนี้ซ้ำ) — บนจอพกกระเป๋าใช้ fire-together ชุดเดียวกันโดยไม่ต้องออกจากจอมืด (components.md 12.1)
   ⤷ เงื่อนไข: เครื่องไม่รองรับ `navigator.vibrate` (iOS บนเว็บ) → ใช้เสียง + ภาพแทน **ห้ามแก้ด้วยการลดเกณฑ์หรือปิด auto-retreat** (F06-R15, pillars Q5/NN-8) — รายละเอียด fallback ของเสียงเป็นของ `audio/cue-list.md` (P2-F06-T13)

C3. **ยาอัตโนมัติ (F06-R12)**: HP หลัง hit ต่ำกว่า `config: economy.autoPotion.defaultThreshold_pct` และมียา (ถุงของ run ก่อน แล้วค่อย inventory) → ดื่มให้เองหนึ่งขวดต่อ hit ผู้เล่นเห็นแค่ toast สั้น `[run.autoPotionUsed]` ("ใช้ยาอัตโนมัติ") HP bar ขยับขึ้นให้เห็นเอง **ไม่มี popup ถามยืนยันก่อนใช้** (ตั้งใจให้ automatic จริง ไม่ขวางจังหวะเดิน) — **Phase 2 ไม่มีทางปรับเกณฑ์หรือปิดยาอัตโนมัติ** (ดูหมายเหตุ override ข้อ 5 และหัวข้อ 5 ของเอกสารนี้)

### 4.2 Auto-retreat (H2, F06-R16..R21)

C4. เปิดอยู่ (ค่าเริ่มต้น) และ HP สุดท้ายหลัง hit ≤ `config: dungeons.hpSafety.autoRetreatThreshold_pct` → run จบทันทีด้วย `exit_reason: auto_retreat` เก็บของครบ (F05-R21) — สัญญาณตอนเกิดเหตุ (ครั้งเดียว ชั่วคราว): overlay/effect สั้น `icon.ui.retreat` (art brief 3.8: "ไม่มีภาพความพ่ายแพ้") แล้วสลับไปหน้าสรุปทันที **ถ้าเกิดพร้อมเงื่อนไขแจ้ง 30% ในจังหวะเดียวกัน ผู้เล่นเห็น/ได้ยินสัญญาณเดียวคือ auto-retreat เท่านั้น** (F06-R16, F05-R18 ข้อ 5 — ไม่ใช่สั่นสองครั้งซ้อนกัน)
   **แก้ B-01 (canon ต้องอยู่บนจอที่ดูได้ทุกเมื่อ ไม่ใช่แค่ overlay ชั่วคราว):** หน้าสรุป (`S-04-run-summary`) แสดงหัวข้อ `[run.summary.autoRetreated]` ("ถอยอัตโนมัติ ของอยู่ครบ" — F04 flow หัวข้อ 7 เป็นเจ้าของหัวข้อนี้) **ต่อด้วยบรรทัดแรกใต้หัวข้อเป็นข้อความ canon เต็มของ GDD `[run.autoRetreat]`** ("HP เหลือต่ำกว่า {autoRetreatPct}% ระบบพาคุณกลับก่อน คุณรอด มอนสเตอร์ไม่ได้ แต่ก็ช่างมันเถอะ" — ห้ามแก้คำ) แล้วตามด้วยรายการของครบตาม F05 B1/B5 — คนที่หยิบมือถือขึ้นมาดูตอนไหนก็ได้หลังเหตุการณ์ (ไม่ใช่แค่ตอน overlay ยังค้างอยู่) ต้องเห็นข้อความ canon นี้ · ไม่เปลี่ยนหัวข้อจอเป็น `run.autoRetreat` (คงหัวข้อสั้น `run.summary.autoRetreated` ของ F04 ไว้ตามเดิม กันผลกระทบต่อ F04-04) — รายละเอียดตำแหน่งเต็มอยู่ flow F05 หัวข้อ 3 ข้อ B5 (แก้ใหม่ในรอบนี้ด้วย) และ wireframe `F04-04-run-state-summary.html`/`F05-02-run-summary-detail.html`

C5. **ผลที่ต้องเป็นจริงบนจอเสมอ**: เปิด auto-retreat ตายจาก hit ไม่ได้ (F06-R17) — ไม่มีเส้นทาง UI ใดที่พาไปหน้าตายถ้า auto-retreat ยังเปิดอยู่

### 4.3 ตาย (H3, F06-R23, **override ข้อ 2 ด้านบน — ไม่มีสถานะล้มในดัน**)

C6. เกิดเมื่อปิด auto-retreat อยู่และ HP ถึง 0 → **run จบทันที** ด้วย `exit_reason: death` (ไม่ใช่สถานะกลางที่ยังอยู่ใน `S-03-run` รอเลือกทำอะไรต่อ) ของในถุง run หายทั้งหมด (F05-R20) exp อยู่ เลเวลไม่ลด → สลับไปหน้าสรุปทันที (`S-04-run-summary`): หัวข้อ `[run.summary.died]` ("คุณตาย ของหายหมด" — label สั้น เจ้าของหัวข้อคือ flow F04 หัวข้อ 7) **แก้ B-01: บรรทัดแรกใต้หัวข้อเป็นข้อความ canon เต็มของ GDD `[run.death]`** ("คุณตาย ของใน run นี้หายทั้งหมด ครั้งหน้าลองกลับบ้านก่อนตาย" — canon ห้ามแก้คำ, ต่างจาก `run.summary.died` ที่เป็นแค่ label หัวข้อสั้น) **ต่อด้วย** `[run.summary.diedBody]` ("EXP ที่ได้ใน run นี้ยังอยู่" — ปิด N-14 ของ F04-flow-approval ตามที่ flow F05 หัวข้อ 3 ข้อ B4 กำหนดไว้แล้ว เอกสารนี้ยืนยันซ้ำเพราะเป็นเนื้อหาของ F06) รายการของว่าง = `[run.summaryRewardLost]` ("ไม่เหลืออะไร") ปุ่มเดียวเด่นสุด `[run.summaryContinue]` กลับแผนที่ **ไม่มีปุ่ม "ใช้ยาฟื้น"/"รอฟื้นเอง"/Support ชุบ อยู่บนจอนี้เลย** (คีย์ `run.death.usePotion`/`waitRecover`/`reviveHint` ไม่ใช้ในหน้านี้ของ Phase 2 — ทางฟื้นทั้งหมดอยู่นอก run ที่จอบ้าน ดู C7) — ลำดับ heading → `run.death` → `diedBody` → รายการว่าง ต้องตรงกันทั้ง `F04-04-run-state-summary.html`, `F05-02-run-summary-detail.html` และเฟรม C6 ของ `F06-03-hp-warning-autoretreat-death-recovering.html` (แก้ทั้งสามไฟล์ในรอบนี้)

F2. เกิดเมื่อไกล **และ** ตำแหน่งอยู่นอก geometry ย่านเปิดตัว (`config: unlocks.home.seeLaunchAreaMask`) แต่ยังอยู่ในรูป playarea mask — ทุกอย่างของ F1 **บวก** ส่วนลงทะเบียนความสนใจรายเขต **แก้ B-05 (คำตัดสิน game-director): ปุ่มนำทางยังคงเป็นปุ่มเด่นสุด (primary) เหมือน F1 ทุกประการ — การลงทะเบียนรายเขตเป็นการ์ดรองใต้แผงนำทาง ไม่ใช่ปุ่มเด่นสุดอีกต่อไป** (เดิมเอกสารนี้ให้ปุ่มยื่นเรื่องเด่นสุด ขัด F06-R52 ข้อ 1–2 ที่ "ทุกอย่างของไกล" ต้องมีปุ่มนำทางเด่นสุดก่อน — คนสถานะนี้ยังมี dungeon จริงให้เดินไป เกมมีไว้ให้คนออกไปเดิน) การ์ดรอง: กรอบ `[home.outsideLaunchTitle]` ("ช่วยกันปลุกย่านเรา") + `[home.outsideLaunchBody]` ("{areaName}ยังไม่มีใครมาสำรวจ ยื่นเรื่องขอเปิดได้ที่นี่") ปุ่มรอง (secondary) `[home.outOfAreaCta]` ("ยื่นเรื่อง") → `S-09-interest-register` โหมดรายเขต (Flow F หัวข้อ 7.4) — เฉพาะ **นอกพื้นที่ (F3) เท่านั้น** ที่ปุ่มยื่นเรื่องยังเด่นสุดได้ตามเดิม เพราะไม่มีการนำทางให้เลือก
   ⤷ เงื่อนไข: geometry ย่านเปิดตัวยังไม่พร้อมในเครื่อง (location-engineer ยังไม่ส่ง mask) → ทุกคนในสถานะไกลเห็นการลงทะเบียนรายเขตนี้ไปก่อน (ไม่มีผลเสีย เพราะไม่มีรางวัลจากการลงทะเบียน, [ASSUMPTION A-P2-F06-T02-1 ของสเปก])
   ⤷ เงื่อนไข: อยู่นอกย่านเปิดตัวแต่ dungeon ที่ใกล้สุดข้ามเขตยังอยู่ในเกณฑ์ (H-E22) → เป็นสถานะ **ใกล้** เล่นปกติ ไม่ใช่กรณีนี้ (ต้องไกลก่อนตามนิยาม R50 ข้อ 2)

### 7.3 นอกพื้นที่ (`S-07-out-of-area-panel`, D-064)

F3. เกิดเมื่ออยู่นอกรูป `config: unlocks.home.seeOutOfAreaMask` เท่านั้น (ไม่ใช่เรื่องระยะ) → แผนที่กรุงเทพ+ปริมณฑลเป็นสี ส่วนนอกเขตเป็นโซนดำมีเส้นแบ่งจังหวัด **นำทางไม่ได้** (GDD "แผนที่และโซนดำ") หัว `[home.outOfAreaTitle]` ("ช่วยกันปลุกจังหวัดเรา") + `[home.outOfAreaBody]` ("{provinceName}ยังไม่มีใครมาสำรวจ ยื่นเรื่องขอเปิดได้ที่นี่") ปุ่มเด่นสุด `[home.outOfAreaCta]` → `S-09-interest-register` โหมดรายจังหวัด (Flow F หัวข้อ 7.4)

F4. **ห้ามแสดง `[home.outOfAreaCount]`/`[home.outOfAreaCountZero]` ในจอนี้ของ Phase 2** (override ข้อ 3 ด้านบน, F06-R56/R57, GD N-04) — ทั้งสอง key มีอยู่แล้วใน `copy.th.json` จาก Phase 1 แต่สงวนไว้ให้ Phase 3 (F23) ที่มี backend นับจริง **ไม่มี element ใดแทนที่บรรทัดนี้ ไม่มีช่องว่างจองไว้** เลย์เอาต์ของ F3 จึงจบที่ปุ่ม "ยื่นเรื่อง" ทันทีหลัง body โดยไม่มีบรรทัดจำนวนคนคั่นกลาง

### 7.4 `S-09-interest-register` — ลงทะเบียนความสนใจ (F06-R52 ข้อ 2/3, R53)

F5. เลือกจาก **รายการเท่านั้น ไม่มีช่องพิมพ์** (F06-R53): โหมดรายจังหวัด (F3) ใช้ `[interest.title]`/`[interest.selectProvince]` โหมดรายเขต (F2) ใช้ `[interest.areaTitle]`/`[interest.selectArea]` — รายชื่อมาจาก content ของหลังบ้าน (level-designer/narrative-designer) **ไม่เก็บพิกัดใดๆ** เก็บแค่ชื่อจังหวัด/เขตที่เลือกใน `kw.p2.*` กดยืนยัน `[interest.confirm]` → `[interest.confirmed]`/`[interest.confirmedArea]` ("ยื่นเรื่องแล้ว {name}เปิดเมื่อไรจะแจ้ง") **ไม่มีของตอบแทนหรือ badge ใดๆ** (F06-R53, pillars 7.3) เปลี่ยนหรือถอนได้ตลอด (กลับมาหน้านี้แล้วเลือกใหม่ทับของเดิม)

### 7.5 ไม่รู้ตำแหน่ง (`S-08-unknown-location-panel`)

F6. เกิดเมื่อไม่มี consent/permission, GPS ปิด หรือ accuracy แย่ต่อเนื่องตาม `config: location.homeState.*` → หัว `[home.unknownTitle]` ("ไม่รู้ว่าคุณอยู่ไหน") + `[home.unknownBody]` ("ไม่มีตำแหน่ง ก็ไม่มีรอยแยกใกล้ตัว แผนที่ยังดูได้") ปุ่มเดียวเด่นสุด `[home.unknownCta]` ("ให้ใช้ตำแหน่ง") → เริ่ม `S-00-consent-location` ใหม่ (**ไม่เด้ง popup ซ้ำเอง** ทุกครั้งที่เปิดแอป — ต้องกดปุ่มนี้เอง) — accuracy แย่ต่อเนื่อง (ไม่ใช่ปฏิเสธ consent) เพิ่ม `[gps.lowAccuracyBody]` อธิบายเหตุ · **แก้ B-04**: ใต้ปุ่มหลักเพิ่มปุ่มรอง (secondary) `[home.unknownRegisterHint]` ("รู้จังหวัดของตัวเองไหม บอกเราได้แม้ไม่เปิดตำแหน่ง") + ปุ่ม `[home.outOfAreaCta]` ("ยื่นเรื่อง") → `S-09-interest-register` โหมด**รายจังหวัด** (เหมือน F3, ไม่ใช่รายเขต เพราะไม่รู้ตำแหน่งจึงไม่รู้ว่าอยู่ในย่านเปิดตัวหรือไม่) — คนที่ปฏิเสธตำแหน่งยังบอกจังหวัดที่อยู่ได้โดยไม่ต้องให้พิกัด (F06-R52 ข้อ 4) ปุ่มนี้**ไม่เด้งเอง ไม่มีรางวัลตอบแทน**

### 7.6 ระยะที่แสดงในทุกสถานะที่บ้านเป็นค่าประมาณ (N-02 ของ board, task context)

F7. ตัวเลขระยะทุกจุดในหัวข้อ 7.1–7.2 (`{distanceText}`) เป็นระยะเส้นตรงปัดขึ้นเป็นขั้นตาม `config: unlocks.home.distanceDisplaySteps_m` เหมือน flow F04 A2 ทุกประการ (ไม่ใช่กฎแยกของจอที่บ้าน) — accuracy ต่ำใช้ `[nav.approximateDistancePrefix]` ("ประมาณ") นำหน้าตามกฎเดียวกัน ยังปัดขึ้นเสมอ ไม่แสดงน้อยกว่าระยะจริง

## 8. Flow G — Consent, age gate, ลบข้อมูลในเครื่อง, Credits (F06-R44..R49, C2-6)

age gate และ consent ตำแหน่งของ onboarding ครั้งแรกอยู่ที่ Flow A ข้อ A2/A3 แล้ว หัวข้อนี้ครอบสิ่งที่เข้าถึงได้ **ทีหลัง** จากหน้าตั้งค่า (ถอน/ให้ consent ใหม่, ลบข้อมูล, Credits) ซึ่งไม่มีเงื่อนไข consent/unlock ใดกั้น (เข้าถึงได้ตั้งแต่ก่อนเล่นเกม, ia.md หัวข้อ 3)

### 8.1 `S-23-privacy` — ถอน/ให้ consent ใหม่ (ใช้โครงเดิมของ ia.md ได้ทั้งหมด)

G1. หัว `[privacy.title]` แสดงสถานะ consent ปัจจุบัน `[privacy.locationStatusLabel]` + `[privacy.locationStatusGranted]`/`[privacy.locationStatusNotGranted]` + คำอธิบาย `[privacy.positionLogExplain]` (TTL, วัตถุประสงค์, ไม่เปิดเผยผู้เล่นอื่น) + ปุ่ม `[privacy.withdrawButton]` ("ถอนความยินยอม") ผ่าน popup ยืนยัน (`privacy.withdrawConfirmTitle/Body/Button`) — ถอนแล้วกลับสถานะไม่รู้ตำแหน่ง (Flow F หัวข้อ 7.5) เข้า dungeon ไม่ได้จนกว่าจะให้ใหม่ + ลิงก์ `[legal.privacyPolicyLink]` เต็ม

**แก้ B-06 (คำตัดสิน game-director J-P2-T30-1): ถอน consent ระหว่างมี run ไม่ถูกบล็อกและไม่ปล่อยไหลเป็น Grace → Suspended → timeout** — ปุ่ม `[privacy.withdrawButton]` กดได้เสมอแม้มี run อยู่ (ต่างจากปุ่มลบข้อมูลในเครื่อง G3/G5 ที่บล็อกระหว่าง run — สิทธิ์ถอน consent ต้องใช้ได้ทุกเมื่อ ตาม NN-7 ในขณะที่ลบข้อมูลรอจบ run ได้เพราะไม่ใช่สิทธิ์เดียวกัน) ถ้ามี run อยู่ตอนกดถอน:
1. popup ยืนยัน (`privacy.withdrawConfirmTitle/Body/Button`) เติมบรรทัดใหม่ `[privacy.withdrawDuringRunNote]` ("run ที่กำลังเล่นอยู่จะจบทันที ของที่เก็บมาอยู่ครบ") บอกผลตรงๆ ก่อนกดยืนยัน
2. กดยืนยัน → หยุดขอตำแหน่งทันที (`consent.location = withdrawn`) **และ run จบทันทีเหมือนกดออกเอง**: เก็บของในถุง run ทั้งหมด (ครบ ไม่ใช่บางส่วน) ใช้ `exit_reason` เดียวกับออกเอง (`manual_exit` หรือค่าใหม่ที่ tech-lead เลือก — ไม่เปลี่ยนการจ่ายตาม F05-R21) **ไม่ใช่** `timeout` และไม่ผ่านสถานะ Grace/Suspended ใดๆ
3. → หน้าสรุป run ปกติ (`[run.summary.exited]` หรือ key ใหม่ถ้า tech-lead แยก) → กลับ `S-01-map` → เห็นสถานะไม่รู้ตำแหน่งทันที (Flow F หัวข้อ 7.5)
4. ต่างจากพฤติกรรมเดิมที่เอกสารนี้เคยเขียนไว้ก่อนรอบนี้ (ปล่อยให้ไม่มีหลักฐานแล้วไหลตาม F04 Grace → Suspended → `timeout`) — พฤติกรรมนั้นสงวนไว้ให้กรณี **สัญญาณ GPS หายเฉยๆ โดยผู้เล่นไม่ได้ถอน consent** เท่านั้น (เช่น เข้าตึก, เครื่องเก็บ GPS ไม่ได้) ซึ่งยังใช้กติกาเดิมของ F04 ไม่เปลี่ยน
5. [handoff tech-lead: `docs/tech/F06-hp-damage-onboarding.md` หัวข้อที่กล่าวถึงการถอน consent ระหว่าง run ("ถ้ามี run อยู่ run ไม่มีหลักฐานแล้วเดินตาม F04 Grace → Suspended → timeout") เขียนไว้ก่อนคำตัดสินนี้ ขัดกับ B-06 — ต้องแก้ให้ตรง เอกสารนี้เป็นตัวจริงสำหรับพฤติกรรมที่ผู้เล่นเห็นจนกว่าจะแก้ tech note]

G2. **Phase 2 ไม่มี consent อื่นในหน้านี้** (D-088 — ไม่มีข้อมูลออกจากเครื่องนอกจาก position sample ที่ใช้ตรวจ movement gate ในเครื่องเอง) ไม่มีลิงก์ไป `S-24-account-delete` เป็นทางเดียวของการลบข้อมูล (ต่างจาก IA เดิมที่โยงไปหน้าลบบัญชี — ดูหมายเหตุ override ข้อ 6) แทนที่ด้วยลิงก์ไปหัวข้อ 8.2

### 8.2 ปุ่ม "ลบข้อมูลในเครื่อง" (ใหม่ของ Phase 2, C2-6 — คนละกลไกจาก `S-24-account-delete`)

## 10. แอปถูกย่อ/ปิด และเน็ตหลุด

- **HP ฟื้น (นอก run) คำนวณจากเวลาที่ผ่านไปตามนาฬิกาของ host รวมช่วงที่แอปปิด** (F06-R04) — ปิดแอปตอน Recovering แล้วเปิดใหม่ 20 นาทีให้หลัง เห็น HP ฟื้นมาตามสัดส่วนเวลาจริงทันที ไม่ต้องรอ "จับเวลาสด" ระหว่างแอปเปิด
- **นาฬิกาเครื่องถูกตั้งย้อน**: HP ไม่ลดจากเหตุนี้ และตั้งจุดเริ่มนับฟื้นใหม่ที่เวลาปัจจุบัน (F06-R04) — เหมือนกฎ `clock_invalid` ของ F04 ที่ใช้กับ run
- **onboarding ถูกปิดแอปกลางทาง** (H-E18, ครอบคลุมในหมายเหตุ override ข้อ 1 + Flow A): เปิดใหม่กลับไปขั้นแรกที่ยังไม่ผ่านเสมอ ไม่เริ่มใหม่ทั้งหมด ยกเว้นกดปุ่ม "ลบข้อมูลในเครื่อง" (Flow G ข้อ G4) โดยตั้งใจ
- **เน็ตหลุดระหว่างจอ F06 ใดๆ**: ไม่มีผลใด (Phase 2 ไม่มี server, engine ในเครื่องล้วน) ยกเว้นการส่ง "ลงทะเบียนความสนใจ" ที่ยังค้าง `interest.pending` จนกว่าจะมี backend จริงใน Phase 3 (F23) — ไม่บล็อกการกดยืนยันในเครื่อง
