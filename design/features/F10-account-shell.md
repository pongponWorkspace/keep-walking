## 1. ผู้เล่นทำอะไร เห็นอะไร รู้สึกอะไร

- เปิดแอปครั้งแรก เห็นปุ่ม "เริ่มเกม" ปุ่มเดียว (D-144) กดแล้วเจอจอ login ที่หน้าตาเหมือนเกมทั่วไป: ปุ่ม Google, ปุ่ม Apple และลิงก์เล็กสำหรับอีเมล กดอะไรก็ไปต่อได้ทันที ไม่มีหน้าต่างเด้ง ไม่มีอีเมลยืนยัน
- ตอบอายุ ให้สิทธิ์ตำแหน่ง (หรือไม่ให้ก็ได้) แล้วถึงจอสร้างตัวละคร: เลือกพลังหนึ่งในสี่ ตั้งชื่อเอง หรือกดสุ่มถ้าคิดไม่ออก เกมเตือนสั้นๆ ว่าอย่าใช้ชื่อจริง ถ้าพิมพ์เบอร์โทรหรือคำหยาบ เกมบอกทันทีว่าผิดตรงไหน
- เรื่องเล่าห้าหน้าสั้นๆ แบบแห้งๆ ว่าทำไมกรุงเทพฯ มีรอยแยก กด "ถัดไป" ไปเรื่อยๆ หรือกดข้ามได้ถ้าอยากเดินเลย หน้าสุดท้ายปุ่ม "ออกไปลุย!" พาไปแผนที่
- จากนั้นแผนที่คือบ้าน มีแถบล่างห้าช่อง (Inventory, Upgrade, Map, Shop, Party) สามช่องบอกแค่ว่า "เร็วๆ นี้" มุมบนขวามีเฟืองไปตั้งค่าและออกจากระบบ
- ความรู้สึกที่ต้องการ: "เหมือนเกมจริง แต่ไม่ขวางการออกไปเดิน" · ทุกขั้นเพิ่มต้องสั้นพอที่ผู้เล่นยังถึงรอยแยกแรกตามเป้า 10 นาทีของ F06 (R-F10-4)

## 2. ขอบเขต Phase 2 และหลักที่ต้องถือ

1. **login เป็น shell ไม่มี auth จริง** (D-145) · ทุกปุ่ม bypass ในเครื่อง ไม่มี request ไป Google, Apple หรือบริการอีเมลใด · auth จริงเป็นของ F07 Phase 3
2. **ไม่เก็บ password ไม่เก็บอีเมล ไม่เก็บ token** ทั้งใน storage, telemetry และ export (P-1) · สิ่งที่เก็บจาก login มีแค่ provider ที่เลือกและธงว่า signed in
3. age gate ก่อน consent ตำแหน่ง ก่อน permission ยังอยู่ครบ (F06-R44 คำตัดสิน 10.2, NN-7) · F10 แทรกขั้นรอบๆ ได้ แต่สลับสามขั้นนี้ไม่ได้
4. ชื่อตัวละครเป็นช่องพิมพ์ช่องเดียวของเกม อยู่ในเครื่องเท่านั้น ไม่แสดงให้ผู้เล่นอื่น ไม่อยู่ใน telemetry/export · ไม่ใช่ช่องทางสื่อสาร จึงไม่ใช่ free-text chat (NN-4 · หัวข้อ 5 คำตัดสิน 6)
5. F10 ไม่แตะ movement gate, reward tick, HP, run state (NN-1, NN-2, NN-8) · การจบ run ที่ F10 ก่อได้มีทางเดียวคือ `manual_exit` (R42)
6. ค่าตัวกรองชื่อ, คลังชื่อสุ่ม, รายการคำต้องห้าม, ป้ายทุกจอ มาจาก config/content/copy (NN-3)
7. F10 ไม่มีรางวัลใด ไม่มีของแรกเข้า ไม่มีโบนัส login (GDD หลักการข้อ 2)

## 3. กฎ (ทดสอบได้)

### 3.1 ลำดับ onboarding (D-149)

- F10-R01 ลำดับครั้งแรกมี 8 ขั้น เรียงตายตัว: (1) เริ่มเกม `O-start` → (2) login `O-login` → (3) ยืนยันอายุ `O-age` → (4) consent ตำแหน่ง `O-consent` → (5) permission เบราว์เซอร์ `O-permission` → (6) สร้างตัวละคร `O-character` → (7) เรื่องเล่า `O-story` → (8) แผนที่ `O-map` · หลังขั้น 8 onboarding ของ F06 เดินต่อตามเดิม (`O-nearest`/`O-home` → `O-first-run` → `O-done` ที่รางวัลก้อนแรก F06-R39, R40)
- F10-R02 แต่ละขั้นเป็นจอเดียว ปุ่มเด่นเดียว (ยกเว้นจอ login ที่ปุ่ม Google และ Apple เป็นกลุ่มปุ่มหลักน้ำหนักเท่ากัน R08) · ไม่มีขั้นใดข้ามได้ยกเว้น (5) ตาม R03 และ (7) ตาม R27
- F10-R03 ปฏิเสธ consent ที่ขั้น 4 → ข้ามขั้น 5 ไปขั้น 6 ทันที ผู้เล่นอยู่สถานะไม่รู้ตำแหน่ง (F06-R48, R50 ข้อ 4) · สร้างตัวละครและดูเรื่องเล่าได้ครบ · ถึงแผนที่ในสถานะไม่รู้ตำแหน่งพร้อมปุ่มกลับไปให้ consent (F06-R52 ข้อ 4)
- F10-R04 permission ถูกบล็อกหรือ GPS ไม่พร้อมที่ขั้น 5 ไม่ทำให้ onboarding ติด · ไปขั้น 6 ต่อในสถานะไม่รู้ตำแหน่ง
- F10-R05 เปิดแอปใหม่กลางทาง (reload, ปิดแอป, OS kill) กลับไปขั้นแรกที่ยังไม่ผ่าน**ตามข้อมูลที่เก็บแล้ว** ไม่เริ่มใหม่ทั้งหมด (แทน F06-R36 ส่วนลำดับ) · ขั้นที่นับว่าผ่าน: (1) เมื่อ F06 บันทึก intro · (2) เมื่อ account ถูกเขียน ซึ่งเกิดหลังผ่าน (3) เท่านั้น (R13) · (3)(4)(5) ตาม F06 · (6) เมื่อกดสร้างตัวละครสำเร็จ · (7) เมื่อจบหรือข้ามเรื่อง
- F10-R06 route ของ nav และ Setting (R31–R39) ใช้ได้เมื่อผ่านขั้น 1–7 แล้วเท่านั้น (เรียกว่า "shell พร้อม") · ก่อนนั้นทุก deep link พาไปขั้นแรกที่ยังไม่ผ่าน · ข้อยกเว้นเดียว: หน้าที่ flow F06 ให้เข้าถึงได้ระหว่าง onboarding อยู่แล้ว (เช่น privacy policy ตาม pillars U7) คงเดิม

### 3.2 จอเริ่มเกมและ login (D-144, D-145)

- F10-R07 จอเริ่มเกมตาม D-144 (ทำแล้วใน P2-X59): ปุ่ม "เริ่มเกม" ปุ่มเดียว `onboarding.introStart` · แตะนอกปุ่มไม่ไปต่อ · กดแล้วไปจอ login
- F10-R08 จอ login มี: ปุ่ม Google และปุ่ม Apple เป็นทางหลัก · ลิงก์รองไปจอ email login · ป้ายปุ่มตามนโยบายแบรนด์ของ art-director (P2-F10-T02: ไม่วาดหรือดัดแปลง logo เอง)
- F10-R09 จอ email login มีช่องอีเมล ช่อง password ปุ่มเข้าสู่ระบบ และลิงก์ไปจอสมัคร (register) กับจอลืมรหัสผ่าน (forgot) · จอสมัครมีช่องอีเมลและ password · จอลืมรหัสผ่านมีช่องอีเมลช่องเดียว · ทุกจอย่อยมีทางกลับจอ login หลัก
- F10-R10 **ผลของทุกปุ่มยืนยันบนทั้งสี่จอ = bypass ไปขั้นถัดไป (ขั้น 3 ยืนยันอายุ)** ได้แก่ Google, Apple, เข้าสู่ระบบด้วยอีเมล, สมัคร, ส่งคำขอลืมรหัสผ่าน · ไม่มีปุ่มใดพาไปจอ error, จอรออีเมล หรือจอยืนยันตัวตน
- F10-R11 Phase 2 ไม่ตรวจรูปแบบและไม่บังคับกรอกช่องอีเมล/password · ปุ่มยืนยันทำงานแม้ช่องว่าง · ค่าที่พิมพ์ถูกทิ้งทันทีที่ออกจากจอ ไม่เขียนลง storage ใด ไม่อยู่ใน telemetry ไม่อยู่ใน URL และไม่ถูกส่งออก (P-1) · ช่อง password เป็นแบบซ่อนตัวอักษร และไม่ชวน browser ให้บันทึกรหัส (วิธีเป็นของ tech-lead)
- F10-R12 กดปุ่ม Google หรือ Apple ไม่เปิด popup ไม่ redirect ไม่มี network request ไป origin นอก allowlist (C2-1) · copy ของจอสมัครและลืมรหัสผ่านไม่สัญญาว่ามีอีเมลส่งจริง ไม่สัญญาว่าข้อมูลย้ายข้ามเครื่องได้ (R-F10-1, ถ้อยคำของ narrative-designer)
- F10-R13 **account เขียนลงเครื่องหลังผ่าน age gate เท่านั้น** (P-2, คำตัดสิน ง) · ระหว่างขั้น 2 ถึงขั้น 3 วิธีที่เลือกถืออยู่ในหน่วยความจำ · ผ่านอายุ → เขียน provider (`google` / `apple` / `email` · สามปุ่มของอีเมลนับเป็น `email`) และธง signed in · ต่ำกว่าเกณฑ์ → ทิ้ง ไม่เขียน
- F10-R14 ต่ำกว่าเกณฑ์อายุ: จอ "ยังเปิดใช้ไม่ได้" ตาม F06-R46 ไม่เปลี่ยน · ปุ่มเดียวกลับจอเริ่มเกม · หลังจากนั้นเครื่องต้องไม่มี account, ชื่อตัวละคร หรือ key ใหม่ใดของ F10 (R46)

### 3.3 สร้างตัวละคร (D-146 · แทน class sheet ของ F06-R29/R44)

- F10-R15 จอเดียวมีสามส่วนเรียงบนลงล่าง: เลือก class · ช่องชื่อพร้อมปุ่มสุ่มและคำเตือน · ปุ่มเด่น "สร้างตัวละคร" · ไม่ทับแผนที่ (ต่างจาก sheet เดิม เพราะขั้น 6 มาก่อนแผนที่ตาม D-149)
- F10-R16 class: การ์ด 4 ใบ Tanker, Ranged, Support, Magic · ไม่มีค่าเลือกให้ · คำอธิบายผลหนึ่งบรรทัดต่อ class ไม่มีสูตร ไม่มี % ไม่พูดถึง party/debuff (F06-R32, U6) · เลือกแล้วเปลี่ยนใจได้จนกว่าจะกดสร้าง · class ผ่าน `chooseClass` ของ engine ตัวเดิม
- F10-R17 ช่องชื่อ: พิมพ์เอง · มีคำเตือนถาวรหนึ่งบรรทัดใต้ช่องว่าอย่าใช้ชื่อจริง (ถ้อยคำของ narrative-designer) · ไม่มีค่าตั้งต้นในช่อง
- F10-R18 ตัวกรองชื่อ ทำงานด้วยฟังก์ชันเดียว `validateCharacterName` ใน `packages/shared` (P-4) ค่าจาก `config: character.name.*` และรายการจาก `content: character-names.th` · ไม่ผ่านเมื่อข้อใดข้อหนึ่งจริง และบอกเหตุผลแยกตามข้อ:
  1. สั้นกว่า `config: character.name.minGraphemes` หรือยาวกว่า `config: character.name.maxGraphemes` (หน่วยเป็น grapheme cluster ไม่ใช่ code unit เพื่อให้สระบน/ล่างของไทยไม่ถูกนับเกิน · D-150)
  2. มีอักขระนอกชุดที่อนุญาตใน config (รวม emoji, อักขระควบคุม, zero-width หลัง normalize)
  3. ดูเหมือนเบอร์โทร ตามเกณฑ์ตัวเลขใน config (รวมแบบเว้นวรรคหรือขีดคั่น)
  4. ดูเหมือนอีเมลหรือลิงก์ ตามรูปแบบใน config
  5. มีคำไม่สุภาพหรือคำต้องห้ามในรายการ content หลัง normalize ตามวิธีที่ narrative-designer ระบุ (ตัดช่องว่าง วรรณยุกต์ ตัวซ้ำ)
  - fail-closed: browser ที่ไม่มี `Intl.Segmenter` นับ grapheme ไม่ได้ → ชื่อไม่ผ่านทุกกรณี (รวมชื่อสุ่ม) สร้างตัวละครไม่ได้ ไม่มีทางเลี่ยงด้วยการนับแบบ code unit · จอแสดงว่า browser นี้ไม่รองรับ ไม่ค้าง ไม่ crash (A-P2-F10-T07-2)
- F10-R19 เหตุผลที่ไม่ผ่านแสดงแบบ inline ใต้ช่องทีละหนึ่งเหตุผล (เหตุผลแรกตามลำดับ R18) ไม่ใช้ popup · ไม่แสดงคำต้องห้ามที่จับได้กลับให้ผู้เล่นเห็น · ไม่มีโทษจากการพิมพ์ไม่ผ่านกี่ครั้งก็ตาม
- F10-R20 ปุ่มสุ่มชื่อ: เติมชื่อจาก `randomCharacterName` ลงในช่อง ชื่อที่ได้ผ่าน R18 เสมอ (ถ้าสุ่มครบ `config: character.name.randomMaxAttempts` ยังไม่ผ่าน ใช้ค่าสำรองจาก content) · กดซ้ำได้ไม่จำกัด · แก้ต่อจากชื่อที่สุ่มได้ (แก้แล้วนับเป็นชื่อที่พิมพ์เอง)
- F10-R21 ปุ่ม "สร้างตัวละคร" กดได้เมื่อเลือก class แล้วและชื่อผ่าน R18 · กดแล้ว class และชื่อบันทึกพร้อมกันครั้งเดียว ไปขั้น 7 · ไม่มี popup ยืนยันเพิ่ม (คงจำนวนแตะของ F06)
- F10-R22 ชื่อที่บันทึกคือชื่อหลัง normalize (ตัดช่องว่างหัวท้าย ยุบช่องว่างซ้ำ) · ชื่อไม่ต้องไม่ซ้ำใน Phase 2 (ไม่มี server) · Phase 3 ตรวจซ้ำและกรองซ้ำที่ server (NN-1, R-F10-3)

## 5. คำตัดสินในเอกสารนี้ (authority game-director · ส่ง orchestrator ลง decision log)

รูปแบบ: คำตัดสิน · หลักการ GDD ที่ใช้ตามลำดับ · เหตุผล

1. **(ก) ออกจากระบบระหว่าง run ทำได้ จบ run ด้วย `manual_exit` ทางเดียว** (R42) · หลักข้อ 3: ของอยู่ครบ ไม่ขังผู้เล่นไว้ในหน้าที่ออกไม่ได้ · ข้อ 2 ไม่กระทบ: การจบ run ไม่สร้างรางวัลใหม่ tick ที่ยังไม่ครบไม่ได้อะไรตาม F05 · ใช้ทางเดียวกับการถอน consent (F06-R48 ข้อ 2) จึงไม่มี exit_reason ใหม่ · ทางเลือกที่ไม่เอา: บล็อกจน run จบแบบลบข้อมูล (R49) เพราะ logout ไม่ลบอะไร จึงไม่มีเหตุให้รอ
2. **(ข) login ใหม่หลังออกจากระบบไปแผนที่ตรง** (R43) · หลักข้อ 3 และหลัก "อย่าให้อ่านก่อนเล่น" ของ GDD "10 นาทีแรก": ผู้เล่นผ่านอายุ consent ตัวละคร และเรื่องแล้ว การถามซ้ำคือแรงเสียดทานเปล่า · consent ตำแหน่งยังถอน/ให้ใหม่ได้ในตั้งค่าตาม F06-R48 · อายุไม่ถามซ้ำเพราะ Phase 2 ไม่มีตัวตนจริงให้ผูก ธงอายุเป็นของเครื่องเหมือนข้อมูลอื่น (Phase 3 F07 ย้ายไปผูก account)
3. **(ค) ผู้เล่นเดิมไป login → ตั้งชื่อ (class ล็อก) → เรื่องเล่า → แผนที่ · class แก้ไม่ได้** (R45–R48) · หลักข้อ 3: ไม่ลบของที่เดินได้มา ไม่ถามอายุ/consent ซ้ำ · class ล็อกตาม F06-R30 และ U5 (เปลี่ยน class ห้ามสอนและยังไม่ปลด) · ให้ดูเรื่องเล่าด้วยเพราะเป็นครั้งเดียวที่มีจังหวะนี้ และข้ามได้ (R27) · run ค้างไม่ถูกขัด (หลักข้อ 3)
4. **(ง) account เขียนลงเครื่องหลังผ่าน age gate เท่านั้น** (R13) · NN-7 และ F06-R46: ผู้ที่อายุต่ำกว่าเกณฑ์ต้องไม่มีข้อมูลใดถูกเก็บ · ลำดับใหม่ให้ login มาก่อนอายุ จึงต้องถือวิธีไว้ในหน่วยความจำ · ผลข้างเคียงที่ยอมรับ: reload ระหว่าง login กับอายุต้องกด login อีกครั้ง (หนึ่งแตะ)
5. **(จ) ออกจากระบบ ≠ ลบข้อมูลในเครื่อง** · ออกจากระบบ: ปลดธง signed in เท่านั้น ไป login ทำได้ระหว่าง run (R41, R42) · ลบข้อมูล: ล้าง `kw.p2.*` ทั้งหมดรวม account และชื่อ ไปจอเริ่มเกม ทำได้เมื่อไม่มี run (R44) · เหตุผล: D-148 สั่งว่าข้อมูลตัวละครต้องอยู่หลัง logout · ลบข้อมูลคือสิทธิ์ PDPA (GDD "ข้อมูลตำแหน่ง" ปุ่มลบบัญชีที่ลบจริง) ต้องแยกให้ผู้เล่นไม่สับสนว่ากดอันไหนแล้วของหาย

## 8. Acceptance criteria (สิ่งที่สังเกตได้)

1. ติดตั้งใหม่ แล้วเดินผ่านจอ: เริ่มเกม → login → อายุ → consent → permission → สร้างตัวละคร → เรื่อง 5 slide → แผนที่ ตามลำดับนี้เท่านั้น · ปฏิเสธ consent ไม่เห็นจอ permission และยังถึงแผนที่
2. ทุกปุ่มยืนยันของจอ login, email login, register, forgot พาไปจอยืนยันอายุ (หรือแผนที่เมื่อ `SignedOut`) · ระหว่างกดไม่มี request ออกไปนอก allowlist (ตรวจ network log)
3. หลังกรอกอีเมล/password แล้วผ่านทั้ง flow: ค้น localStorage, sessionStorage, IndexedDB, telemetry buffer, export และ URL ไม่พบค่าที่พิมพ์ · `kw.p2.account` มีแค่ provider + ธง signed in (+ schemaVersion)
4. ตอบอายุต่ำกว่าเกณฑ์หลังกด login: ไม่มี account ชื่อตัวละคร หรือ key ใหม่ของ F10 ในเครื่อง
5. ชื่อตัวละคร: ผลของ `validateCharacterName` ตรงทุก vector ใน `design/systems/test-vectors/character-name.json` · จอแสดงเหตุผลตรงกับผล · ปุ่มสุ่ม 10,000 seed ได้ชื่อที่ผ่านทุกครั้ง · ปุ่มสร้างกดไม่ได้จนกว่าเลือก class และชื่อผ่าน
6. ค้น telemetry และ export ไม่พบชื่อตัวละคร · ไม่มีจอใดของผู้อื่นแสดงชื่อ (Phase 2 ไม่มีจอผู้อื่น)
7. เรื่องเล่า: slide 1–4 มี "ถัดไป" และ "ข้าม" · slide 5 มี "ออกไปลุย!" · ทั้งจบและข้ามถึงแผนที่ และเปิดแอปใหม่ไม่เห็นเรื่องอีก · copy gate ยืนยันว่าไม่เอ่ยระบบห้ามสอน
8. nav 5 ช่องตามลำดับ R32 เห็นบนแผนที่ Inventory และจอเร็วๆ นี้ · ไม่เห็นบนจอ onboarding, popup confirm, จอ run ทุกสถานะ, จอพกกระเป๋า, สรุป run ที่ 360 และ 390 px · Setting ไม่ทับ HUD
9. จอเร็วๆ นี้ทั้งสามไม่มีกลไก เงื่อนไขปลด ตัวเลข หรือจำนวนคน
10. ออกจากระบบนอก run: ไปจอ login ข้อมูลเดิมครบ · login ใหม่ถึงแผนที่ตรงโดยไม่เห็นอายุ consent ตัวละคร หรือเรื่อง · ระหว่าง run: run จบ `manual_exit` ของครบ ไม่มี trace ใดไหลเป็น Grace/Suspended/`timeout`
11. ลบข้อมูลในเครื่อง: ไม่เหลือ key `kw.p2.*` · เปิดแอปเห็นจอเริ่มเกม · ปุ่มใช้ไม่ได้ระหว่าง run
12. ผู้เล่นเดิม (seed ผ่าน onboarding F06 มี class และ inventory): เปิดแอป → login → ตั้งชื่อโดย class ล็อก → เรื่อง → แผนที่ · inventory, HP, สรุป run ไม่เปลี่ยน · มี run ค้างเล่นต่อได้ก่อน
13. diff ของ F10 ไม่แตะ reward, movement gate, HP, run state (tech gate ตรวจ) · ทุกค่าตัวกรองและป้ายอ่านจาก config/content/copy (config-lint, lint:copy)
