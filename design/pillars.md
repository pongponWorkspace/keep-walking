## 1. เป้าหมายเดียวของเกม

**เกมนี้มีขึ้นเพื่อให้คนออกไปเดิน** (GDD "ภาพรวมและหลักการออกแบบ") ทุกกลไก ทุกหน้าจอ ทุกรางวัล ต้องตอบได้ว่าช่วยให้คนเดินมากขึ้นหรือเดินได้นานขึ้นอย่างไร ถ้าตอบไม่ได้ ฟีเจอร์นั้นไม่เข้า v1

Core loop ที่ทุก feature ต้องเสียบเข้าได้ (GDD "Core loop")
เปิดแอปดู dungeon ใกล้ตัว → เดินไปถึง confirm เข้า → เดินอยู่ข้างในรับ reward tick → ออก / auto-retreat สรุปรางวัล → ตีบวก ขายของ อัปเกรด (ทำที่บ้านได้) → กลับไปเปิดแอป

Tagline ที่สรุปเจตนา: "ออกไปเดิน ช่วยกันปิดรอยแยก แล้วกลับบ้านก่อนฝนตก" (GDD "เรื่องเล่า" · ถ้อยคำสุดท้ายเป็นของ narrative-designer)

## 2. Design pillars

แต่ละ pillar มี: ผู้เล่นรู้สึกอะไร · design ต้องทำอะไร · อะไรที่ถือว่าละเมิด (ใช้เป็นเกณฑ์ตก design gate)

### P1 · เดินจริงเท่านั้นที่นับ
- ผู้เล่นรู้สึก: "ทุกของที่ได้ ได้เพราะเราเดินจริง" คนที่เดินมากเก่งกว่าอย่างชอบธรรม คนที่โกงไม่ได้เปรียบ
- design ต้อง: ผูกทุกรางวัล (exp, drop, gold, contribution ของ raid, ของบอส) กับ movement gate ตัวเดียว (`config: dungeons.movementGate.*`) · ไม่มีเพดานเวลาและไม่มี diminishing return ต่อ run หรือต่อวัน (GDD "ไม่มีเพดานเวลาและไม่มี diminishing return") · คุมเศรษฐกิจแทนการคุมรางวัล
- ละเมิดเมื่อ: มีรางวัลใดไม่ผ่าน gate (login รายวัน, ของจากการดูโฆษณา, รายได้ idle ที่บ้าน, นำเข้าก้าวจากแอปสุขภาพ) · client คำนวณรางวัลเอง · เพดานรายวันที่ลงโทษคนเดินมาก

### P2 · มาถึงแล้วต้องได้เล่น
- ผู้เล่นรู้สึก: "นั่งรถเมล์มา 40 นาทีแล้วคุ้ม" เกมไม่แกล้ง เน็ตหลุดไม่เท่ากับเกมโอเวอร์
- design ต้อง: auto-retreat เปิดเป็น default (`config: dungeons.hpSafety.autoRetreatThreshold_pct`) · แจ้งเตือนก่อนถอย (`config: dungeons.hpSafety.lowHpWarningThreshold_pct`) · กดออกได้ทุกเมื่อโดยไม่ต้องเดินออก · Grace และ Suspended รองรับ GPS drift และธุระสั้น (`config: dungeons.runState.graceMax_s`, `config: dungeons.runState.suspendedMax_s`) · ไม่บล็อกการเข้า dungeon ด้วยเลเวล · ของไม่แตกเมื่อตีบวก · แยก run state กับ connection state
- ละเมิดเมื่อ: บทลงโทษที่ทำให้ผู้เล่นที่ไม่ได้ตั้งใจเสี่ยงเสียของ · ต้องเดินออกจาก polygon ถึงจะจบ run · run ถูกล้างเพราะเน็ตหลุด · ต้องปลดล็อกด้วยเลเวลก่อนเข้า dungeon ใกล้บ้าน

### P3 · อยู่ในที่เดียวกันก็คือเล่นด้วยกัน
- ผู้เล่นรู้สึก: "มีคนอยู่ 3 คน กดเข้าร่วมแล้วเก่งขึ้น" โดยไม่ต้องรู้จัก ไม่ต้องนัด ไม่ต้องเจอหน้า และคนเลเวลสูงอยากให้คนใหม่อยู่ใกล้ เพราะตัวเองก็ได้ buff
- design ต้อง: Nearby Party กดแล้วเข้าเลย ไม่มี invite · แสดงแค่จำนวนและ role ระดับ dungeon · buff stacking ทำให้การช่วยคนอื่นเป็นประโยชน์กับตัวเอง (GDD "สูตร buff stacking", หลักการข้อ 4) · สื่อสารด้วย quick command 10 อันเท่านั้น
- ละเมิดเมื่อ: แสดงชื่อหรือตำแหน่งรายบุคคล · มีช่องพิมพ์ข้อความอิสระ · กลไกบังคับให้คนแปลกหน้าเจอกันจริง (ต้องยืนใกล้กัน, ต้องสแกนกัน) · อันดับหรือกิจกรรมที่ผู้เล่นแย่งทรัพยากรกันเอง · PvP ทุกรูปแบบ

### P4 · มือถืออยู่ในกระเป๋า
- ผู้เล่นรู้สึก: "เดินเล่นตามปกติ เปิดดูเป็นระยะ" ไม่ต้องจ้องจอขณะเดิน ปลอดภัยและไม่เปลืองแบต
- design ต้อง: เล่นเป็น session ที่ผู้เล่นตั้งใจเปิด (web ไม่มี background location) · ระหว่าง run บนเว็บใช้ Screen Wake Lock + "จอพกกระเป๋า" เป็นค่าเริ่มต้น และใช้การเตือนให้เปิดจอค้างเป็นทางสำรองเมื่อ Wake Lock ใช้ไม่ได้ (D-063, design gate A 4.4) · ช่วงที่หน้าเว็บ hidden ไม่นับระยะ ไม่ย้อนเติม · ไม่มี BGM หรือ ambient loop มีแค่ cue สั้นแบบ one-shot (D-052) · รางวัลเป็นขั้นทุก tick (`config: dungeons.rewardTick.rewardTickInterval_s`) ไม่ใช่รายวินาที · สื่อสารจังหวะสำคัญด้วยการสั่นก่อนเสียงและภาพ · ไม่มี animation ต่อเนื่องบนแผนที่ · speed lock เป็นการล็อกการเล่น ไม่ใช่แค่เตือน (`config: anticheat.speedLock.speedLock_kmh`)
- ละเมิดเมื่อ: กลไกที่ต้องกดหรือแตะขณะเดิน (ปุ่มโจมตี, mini-game, จับเวลาให้กด) · AR ผ่านกล้อง · การแจ้งเตือนที่เรียกให้มองจอบ่อยกว่าจังหวะ tick หรือเหตุการณ์ HP · ชวนให้เข้าไปในพื้นที่อันตรายหรือเวลาที่สถานที่ปิด

### P5 · กรุงเทพจริง เล่าแบบแห้ง
- ผู้เล่นรู้สึก: "นี่มันสวนแถวบ้านเรา" และขำกับเรื่องที่คนกรุงเทพเจอจริง (รถติด คิวชานม ฝนตก) โดยไม่มีใครเป็นผู้ถูกเลือก
- design ต้อง: dungeon เป็นพื้นที่สาธารณะกลางแจ้งจริง ชื่อฐานเป็นชื่อจริงบวกคำขยาย และทุกชื่อมาจากหลังบ้าน · copy สั้น กวน ไม่ปลอบ ไม่ด่า ตามกฎ 6 ข้อ (GDD "โทนและภาษาในเกม") · ระบบที่ดูดเงินพูดตรงๆ ว่าดูดเงิน (GDD "ระบบตีบวก")
- ละเมิดเมื่อ: แตะศาสนา การเมือง หรือแบรนด์จริงโดยไม่มี decision ของ HUMAN · dungeon อยู่ในหรือทับเขตวัดและศาสนสถาน รวมงานวัด (D-006) หรือสถานที่ต้องห้ามอื่นใน GDD "สถานที่ที่ไม่ควรเป็น dungeon" · lore ยาวก่อนได้เล่น · ผู้เล่นถูกเขียนเป็นวีรบุรุษ

## 3. หลักการตัดสิน 5 ข้อของ GDD (ใช้ตามลำดับ)

ยกจาก GDD "หลักการที่ใช้ตัดสินทุกข้อขัดแย้ง" โดยคงลำดับเดิม เมื่อสองทางเลือกขัดกัน ให้ไล่จากข้อ 1 ลงไป ข้อแรกที่ชี้ทางได้ชัดเป็นตัวตัดสิน ข้อที่ไม่เกี่ยวให้ข้ามและเขียนไว้ว่าข้าม

1. **ไม่จำกัดสิ่งที่ผู้เล่นได้ จำกัดเฉพาะสิ่งที่ไหลเข้าเศรษฐกิจส่วนกลาง** — คนขยันแข็งแกร่งกว่าได้โดยไม่มีเพดาน แต่ gold ที่ไหลเข้าตลาดต้องคุม
2. **รางวัลผูกกับการเคลื่อนไหวจริงเสมอ** — ทุกระบบที่ให้ของผ่าน movement gate เดียวกัน ไม่มีข้อยกเว้น
3. **ต้นทุนการเดินทางสูง บทลงโทษจึงต้องต่ำ** — ระบบต้องไม่ทำให้คนมาถึงแล้วเล่นไม่ได้
4. **คนเก่งเป็นประโยชน์กับคนอื่น** — ผู้เล่นเลเวลสูงเพิ่มคุณค่าให้ทุกคนรอบตัว ไม่แย่งทรัพยากร
5. **ไม่บังคับให้คนแปลกหน้าเจอกัน** — อยู่ในกรอบสถานที่เดียวกันถือว่าเล่นด้วยกันแล้ว

รูปแบบการเขียนเมื่อใช้หลักการ (ทุก spec และ decision): "หลักการที่ใช้: ข้อ 1 ไม่เกี่ยว · ข้อ 2 ชี้ไปที่ X เพราะ ... → เลือก X" · ถ้าผลขัดกับข้อความใน GDD ต้องเสนอ decision authority HUMAN เสมอ แม้หลักการจะชี้ชัด

## 4. Non-negotiables

ห้ามแลกกับอะไรทั้งสิ้น ฟีเจอร์ที่ละเมิดข้อใดข้อหนึ่งตก design gate ทันที ข้อ NN-1 ถึง NN-7 ตรงกับ `CLAUDE.md` · NN-8 คือกฎคู่ที่ GDD บังคับให้ระบุชื่อ

| # | Non-negotiable | หัวข้อ GDD | สิ่งที่ design gate ตรวจ |
| --- | --- | --- | --- |
| NN-1 | **Server-authoritative** client ส่งแค่ตำแหน่ง + timestamp · damage, drop, contribution, รางวัล และ movement gate คำนวณที่ server | "หลักการที่ห้ามละเมิด", "ข้อจำกัดที่กำหนดรูปร่างของ design" | spec ไม่มีประโยคที่ให้ client ตัดสินผลรางวัล · ผลที่คำนวณบน client ใน Phase 2 เป็นต้นแบบ ไม่ย้ายเข้า account |

### NN-8 กฎคู่ auto-retreat + movement gate (รายละเอียด)
เหตุผล: auto-retreat ที่เปิดเป็น default ทำให้การวางมือถือทิ้งไว้ใน dungeon ปลอดภัยสมบูรณ์ movement gate จึงเป็นสิ่งเดียวที่กันการฟาร์มแบบไม่เดิน ในทางกลับกัน ถ้ามี movement gate แต่ไม่มี auto-retreat คนที่ทำตามที่เกมบอก (มือถือในกระเป๋า) จะตายโดยไม่รู้ตัวและเสียของทั้ง run
1. ทุก mode ที่มีรางวัล (dungeon, raid, dungeon ชั่วคราว, event) ต้องมีทั้ง movement gate และ auto-retreat default เปิด
2. การเปลี่ยนค่า config ของฝั่งใดฝั่งหนึ่งที่ทำให้อ่อนลง (gate ผ่านง่ายขึ้น หรือ auto-retreat ช้าลง / ปิดได้ง่ายขึ้น) ต้องประเมินผลต่ออีกฝั่งในเอกสารเดียวกัน และต้องผ่าน game-director
3. ห้ามมี mode ที่ผ่อน gate เพื่อชดเชยอย่างอื่น (เช่น "ฝนตกลด gate ครึ่งหนึ่ง") ถ้าต้องการช่วยช่วงฝน ให้ใช้กิจกรรมที่บ้านที่ไม่ให้รางวัล (หัวข้อ 7)
4. tick ที่ไม่ผ่าน gate แสดงให้ผู้เล่นเห็นโดยไม่ลงโทษ (ไม่หัก HP เพิ่ม ไม่ริบของเดิม)

### 6.2 รายการห้ามสอน (8 หมวด) และเงื่อนไขปลด
"ห้ามสอน" หมายถึง: ไม่มี tutorial, ไม่มี popup แนะนำ, ไม่มีปุ่มหรือแท็บที่พาไปหน้าของระบบนั้น, ไม่มี copy ใน `onboarding.*` ที่เอ่ยถึง, ไม่มี push แจ้งเตือนของระบบนั้น จนกว่าเงื่อนไขปลดใน config จะผ่าน · เงื่อนไขปลดทุกข้อเป็น config ของ systems-designer ห้ามเขียนเลขใน spec หรือโค้ด

**ข้อยกเว้น: จอ "เร็วๆ นี้" (D-148, F10 คำตัดสิน 8, F10-R35–R38)** · แท็บ Upgrade, Shop, Party ใน nav ล่างที่พาไปจอ "เร็วๆ นี้" ไม่นับเป็น "ปุ่มหรือแท็บที่พาไปหน้าของระบบนั้น" เพราะจอนั้นไม่ใช่หน้าของระบบ · คงข้อยกเว้นได้เฉพาะเมื่อจอครบทุกเงื่อนไข: (1) มีแค่หัวจอ ข้อความหนึ่งบรรทัด และ nav ไม่มีปุ่มอื่น ช่องลงทะเบียน หรือรางวัล (2) ไม่อธิบายกลไก ไม่บอกเงื่อนไขปลด ไม่มีตัวเลข ไม่มีวันที่สัญญา (3) จอ Party ไม่มีจำนวนคน role ของผู้อื่น หรือ placeholder ที่ชวนเดา (NN-4, D-089) (4) ไม่มี badge ตัวเลข หรือ push ชวนเข้าจอ (5) nav ไม่แสดงใน onboarding ขั้น 1–7 และจอ run ทุกสถานะ (F10-R33) · ขาดข้อใด = นับเป็นการสอน U1/U2/U6 หรือร้าน NPC · เมื่อระบบจริงเปิดใน phase หลัง แท็บนั้นกลับอยู่ใต้เงื่อนไขปลดตามตารางด้านล่างตามเดิม · ถ้า playtest พบว่าคนใหม่เสียเวลาในจอเร็วๆ นี้ก่อนออกเดิน product-manager ยกเป็นคำถาม

**"run ที่นับ" (counted run)** ที่ใช้ใน `minCompletedRuns` ทุกข้อ: run ใน dungeon ที่จบแล้วด้วยสาเหตุใดก็ได้ (จบปกติ, auto-retreat, ออกเอง, ตาย, ถูกปิดโดยผู้ดูแล, ปิดฉุกเฉิน) และมี reward tick ที่ผ่าน movement gate อย่างน้อย 1 ครั้ง · run ที่ไม่มี tick ผ่าน gate ไม่นับเลยไม่ว่าจบด้วยเหตุใด · นิยามเดียวอยู่ที่ `config/balance/unlocks.json` → `_meta._note` (design gate A F-15) · server เป็นผู้ประเมิน และการปลดเป็นถาวร · ผลคือการปลดทุกขั้นผูกกับการเดินจริง (หลักการข้อ 2)

#### ร้าน NPC: ขั้นของ core loop ที่เลื่อนไปจบ run แรก ไม่ใช่ระบบห้ามสอน (D-065, design gate A 4.9)
| id | ระบบ | เงื่อนไขปลด | เจตนาของการปลด | หลังปลด |
| --- | --- | --- | --- | --- |
| NPC | ร้าน NPC (ขายวัตถุดิบให้ NPC ราคาคงที่ + ซื้อยา) | `config: unlocks.npcShop` · ปลดเมื่อจบ run ที่นับครั้งแรก | GDD แยก "ตลาด" (แลกเปลี่ยนระหว่างผู้เล่น) ออกจากการขายให้ NPC (gold source หลัก) และยา (gold sink หลัก "ใช้ทุก run") · core loop มี "ขายของ" ต่อจากสรุปรางวัลทันที · เลื่อนถึงจบ run แรกเพราะก่อนนั้นยังไม่มีของให้ขาย ไม่ใช่เพื่อซ่อนระบบ | ใช้ที่บ้านได้ · ไม่จำกัดการขายต่อวัน (GDD "มาตรการคุมเงินเฟ้อ", ค่าอยู่ที่ `config: economy.npcPricing` และ `config: economy.potions`) · ไม่อยู่ใน flow นาที 0–10 |

คำตัดสินเรื่องรหัส: ร้าน NPC **ไม่ได้รับเลข U** ใช้ id `NPC` ถาวร (ไม่ใช่ชั่วคราว) · เหตุผล: U1–U8 คือรายการห้ามสอนที่มาจาก GDD "10 นาทีแรกของคนใหม่" บวกสองหมวดที่เอกสารนี้เพิ่ม (U7, U8) ส่วนร้าน NPC ไม่อยู่ในรายการห้ามสอนของ GDD ถ้าให้เลข U จะทำให้ role อื่นอ่านว่าเป็นระบบที่ "ห้ามสอน" และอาจล็อกนานขึ้นในอนาคต ซึ่งขัดหลักการข้อ 3 (ต้องซื้อยาได้เร็ว) · หลักการที่ใช้: ข้อ 1 ไม่เกี่ยว (NPC ไม่ใช่ตลาดส่วนกลาง) · ข้อ 2 ไม่กระทบ (ขายได้เฉพาะของที่ได้จากการเดิน) · ข้อ 3 ชี้ให้แยกออกจากกลุ่ม U → id `NPC` · ข้อ 4, 5 ไม่เกี่ยว

รูปแบบเงื่อนไขปลดใน config: `config: unlocks.<system>` เป็น object ที่มี `minLevel` และ `minCompletedRuns` (ต้องผ่านทุกข้อ) บวก key เสริมเฉพาะระบบ เช่น `unlocks.partyDetail.minNearbyPartyJoins`, `unlocks.antiCheatHelp.unlockOnEvents` · ทุกระบบใน U1–U8 และร้าน NPC มี object ใน `config/balance/unlocks.json` แล้ว (v3)

ลำดับปลด (ตัดสินแล้วใน design gate A 4.1 · D-040, D-041, D-065 ACCEPTED) · ทุกขั้นต้องผ่าน run ที่นับอย่างน้อย 1 run ก่อน · เลเวลและจำนวน run อ่านจาก config ไม่เขียนเลขใน spec
1. จบ run ที่นับครั้งแรก: ร้าน NPC (`unlocks.npcShop`) และ lore (`unlocks.lore`)
2. การลงแต้ม stat (U4) และกลไก party ละเอียด (U6, ต้องเคยได้ buff จาก Nearby Party จริงด้วย)
3. ตีบวก (U2) และหน้าประกาศ raid + push (U3, ต้องมี run ที่นับมากกว่าขั้นอื่นตาม `unlocks.raid.minCompletedRuns`) · การเข้าร่วม raid ทางกายภาพไม่ถูกล็อกในทุกขั้น (D-040) ผู้เล่นที่ยังไม่ปลดไม่เห็นวงบอสบนแผนที่และไม่ได้ push raid แต่ถ้าเดินเข้าวงบอสจริงจะได้ popup เลือกเหมือนการเข้า dungeon
4. ตลาดผู้เล่น (U1)
5. เปลี่ยน class (U5) มาหลัง U4 เพราะการเปลี่ยน class reset stat
6. anti-cheat help (U7) ตามเกณฑ์ หรือทันทีเมื่อเจอ speed lock / check-in ถูกปฏิเสธครั้งแรก

ไม่มีขั้นใดเกิดใน 10 นาทีแรก · product-manager เฝ้า "เวลาจนได้ประกาศ raid ครั้งแรก" (design gate A F-16) ถ้าคนใหม่ส่วนมากพลาดเสาร์แรก systems-designer ลด `unlocks.raid.minCompletedRuns` ได้ภายใน config

ตัวตรวจ: script ของ narrative-designer ตรวจคำของทั้ง 8 หมวดใน key `onboarding.*` (P1-F03-T05) · uiux-designer ตรวจว่า flow นาที 0–10 ไม่มีทางไปหน้าของ U1–U8 และร้าน NPC (P1-F03-T16) · IA ใช้ลำดับปลดจากตารางนี้ (P1-F03-T15)

## 7. สถานะที่บ้าน

ที่มา: GDD "10 นาทีแรกของคนใหม่" (ปัญหาที่ยังไม่มีคำตอบ), "แผนที่และโซนดำ", "ข้อจำกัดที่กำหนดรูปร่างของ design" (ฤดูฝน) · เจตนา: คนที่เปิดแอปแล้วยังไปไม่ถึง dungeon ต้องไม่เจอหน้าจอว่าง แต่ต้องไม่ได้รางวัลโดยไม่เดิน หน้าที่บ้านมีไว้ **ทำให้อยากออกไปเดิน** ไม่ใช่ทดแทนการเดิน

### 7.1 นิยามสถานะ
ประเมินเมื่อเปิดแอปและเมื่อตำแหน่งเปลี่ยนเกิน `config: unlocks.home.reevaluateDistance_m` · การคำนวณระยะเพื่อแสดงผลบน client ได้ เพราะไม่มีผลต่อรางวัล

| สถานะ | นิยาม | ตัวอย่าง |
| --- | --- | --- |
| ใกล้ | อยู่ในพื้นที่เล่น และ dungeon ที่เปิดอยู่ตอนนี้ใกล้สุดห่างไม่เกิน `config: unlocks.home.farDungeonThreshold_m` (ระยะเส้นตรงจากตำแหน่งผู้เล่นถึงขอบ polygon ก่อนปัด) | ตัวอย่าง GDD "650 ม." |
| ไกล | อยู่ในพื้นที่เล่น แต่ dungeon ที่เปิดอยู่ใกล้สุดห่างเกิน `config: unlocks.home.farDungeonThreshold_m` · รวมกรณีมี dungeon ใกล้แต่ปิดตามเวลาทำการทั้งหมด (ไกลชั่วคราว: แสดงเวลาเปิดถัดไป) | ตัวอย่าง GDD "3 กิโล" |
| ไกล · นอกย่านเปิดตัว (สถานะย่อย) | ไกล และตำแหน่งอยู่นอก geometry ของย่านเปิดตัว (เสนอ `unlocks.home.seeLaunchAreaMask` · ระหว่างเปิดตัวรายย่าน D-073, D-083) · ได้ทุกอย่างของ "ไกล" บวกลงทะเบียนความสนใจรายเขต | อยู่ในกรุงเทพฯ นอกพระนคร ปทุมวัน บางรัก และไกลจาก dungeon |
| นอกพื้นที่ | ตำแหน่งอยู่นอกพื้นที่เล่น คือนอกรูของ mask โซนดำ `data/map/playarea-mask.geojson` (อ้างจาก `config: unlocks.home.seeOutOfAreaMask` · geometry เดียวกับที่ server ใช้ตาม D-043 · เปิดจังหวัดเพิ่มเปลี่ยนแค่ข้อมูล) · **ไม่ใช่ระยะถึง dungeon** (D-064) · แผนที่ส่วนนั้นเป็นโซนดำ | อยู่ต่างจังหวัด |
| ไม่รู้ตำแหน่ง | ปฏิเสธ consent location, ปฏิเสธ permission เบราว์เซอร์, GPS ปิด หรือ accuracy แย่กว่า `config: location.homeState.maxAccuracy_m` ต่อเนื่องนานเกิน `config: location.homeState.sustainedPoorAccuracy_s` (ค่านี้ใช้แสดงผลที่บ้านเท่านั้น แยกจาก `config: anticheat.checkIn.maxAccuracy_m` ที่ใช้ตรวจ check-in) | ยังไม่ให้ consent |

หมายเหตุ (ตัดสินแล้ว D-064, design gate A 4.5): "นอกพื้นที่" ตัดสินด้วยการอยู่นอก mask พื้นที่เล่นอย่างเดียว · อยู่ในพื้นที่เล่นแต่ dungeon ที่เปิดใกล้สุดไกลเกิน `config: unlocks.home.farDungeonThreshold_m` = "ไกล" เสมอ ไม่ว่าจะไกลแค่ไหน (ยังบอกระยะจริงและนำทางได้) · ห้ามนำเกณฑ์ระยะถึง dungeon กลับมาเป็นเกณฑ์ "นอกพื้นที่" เพราะทำให้คนในจังหวัดที่เปิดแล้วถูกชวนลงทะเบียนเปิดจังหวัดตัวเอง และคนนอกเขตที่ใกล้ dungeon ข้ามเขตถูกแสดงเป็น "ไกล" บนโซนดำ · การตรวจ mask ทำที่ client ได้เพราะเป็นการแสดงผลเท่านั้น (NN-1 ไม่กระทบ)

**เกณฑ์ "ไกล" หลังผล F01 (D-072, D-079, P1-F03-T25 B-01 · ปิด A-P1-F03-T01-1):** ระยะที่ใช้และที่แสดงยังเป็นเส้นตรง (ไม่ใช้ routing engine) แต่ค่า `unlocks.home.farDungeonThreshold_m` ต้องปรับเทียบด้วย route factor ที่วัดได้ (ถ่วงประชากร 1.52) ให้ "ใกล้" เดินจริงไม่เกินโซนเหลืองของ PRD F01 · เพดานจาก D-079 คือไม่เกินราว 1,970 ม. เส้นตรง · ค่าปัจจุบันตั้งโดย systems-designer ใน P2-F06-T01 (อ่านจาก config เท่านั้น) · การเปลี่ยนค่านี้ขึ้นให้เกินเพดานต้องผ่าน game-director · กฎแสดงผล: ระยะบนจอ **ปัดขึ้น** เป็นขั้นเสมอ ไม่ปัดลง มีคำกำกับว่าเป็นระยะเส้นตรง ไม่วาดเส้นจากผู้เล่นถึง dungeon (D-089 เงื่อนไข 1–2, F04-R34–R36) · เทียบเกณฑ์ด้วยระยะก่อนปัด

**Phase 2 ซ่อนจำนวนคน (D-089, GD N-04):** ทุกจอในหัวข้อนี้ไม่แสดงจำนวนผู้เล่นใน dungeon และจำนวนผู้ลงทะเบียนต่อจังหวัดหรือต่อเขต จนกว่ามี backend (F09, F23) · "ไม่แสดง" = ไม่มี element ไม่ใช่ 0 หรือเลขปลอม

### 7.3 สิ่งที่ห้ามในสถานะที่บ้าน (ทุกสถานะ)
1. ห้ามให้รางวัลใดๆ โดยไม่ผ่าน movement gate: ไม่มี login รายวัน, ไม่มีของจากการดู tutorial หรืออ่าน role, ไม่มีรายได้ idle ที่บ้าน, ไม่มี "dungeon ที่บ้าน" หรือ dungeon เสมือน, ไม่มีของหรือ badge จากการลงทะเบียนความสนใจ (ได้แค่การแจ้งเตือนเมื่อจังหวัดเปิด)
2. ห้ามนำเข้าจำนวนก้าวหรือระยะจากแอปสุขภาพหรืออุปกรณ์อื่นมาเป็นรางวัล เพราะข้าม movement gate ตัวเดียวของ server
3. ห้ามลดระยะที่ต้องเดินด้วยเงิน ของ หรือเวลารอ (ไม่มีการ "ดึง" รอยแยกมาใกล้บ้าน)
4. ห้ามแสดงผู้เล่นคนอื่นรอบตัวเพื่อให้รู้สึกไม่เหงา · แสดงได้แค่จำนวนคนระดับ dungeon เหมือนในเกมปกติ
5. ห้ามช่องพิมพ์อิสระในการลงทะเบียนความสนใจ
6. ตีบวก ตลาดผู้เล่น และร้าน NPC ที่บ้านใช้ได้เพราะไม่สร้างของใหม่เข้าเกม ใช้แค่ของที่ได้จากการเดินแล้ว (หลักการข้อ 1 และ 2) · ห้ามเพิ่มกิจกรรมที่บ้านที่สร้าง gold, exp หรือวัตถุดิบใหม่ รวมถึงการเพิ่มราคาขาย NPC หรือลดภาษีตลาดเป็นมาตรการช่วงฝน (design gate A F-06)

### 7.4 เจตนาต่อหน้าจอ (ให้ uiux-designer และ narrative-designer)
- "ไกล" ต้องพูดความจริงเรื่องระยะ และให้ทางเลือกที่เป็นการเดิน: นำทาง, ดูเวลาเปิด, บอกว่าเมื่อไปถึงจะเจออะไร · โทนแซะได้แต่ไม่ทำให้รู้สึกว่าเกมไม่ใช่ของเขา
- "นอกพื้นที่" ใช้กรอบ "ช่วยกันปลุกจังหวัดเรา" ตาม GDD "แผนที่และโซนดำ" (แสดงจำนวนคนลงทะเบียนต่อจังหวัดได้เมื่อมี backend · Phase 2 ไม่แสดงตามหัวข้อ 7.1 · ไม่แสดงเกณฑ์เปิดเป็นตัวเลขจนกว่า F23 กำหนด) · "นอกย่านเปิดตัว" ใช้กรอบเดียวกันระดับเขต "ช่วยกันปลุกย่านเรา" (D-073)
- "ไม่รู้ตำแหน่ง" ไม่ตื๊อขอ consent ซ้ำทุกครั้งที่เปิด มีปุ่มเดียวให้กลับไปให้ consent ได้เอง
- ทุกสถานะมีทางเดียวที่เด่นที่สุดบนจอ: ทางที่พาไปสู่การเดิน

### 7.5 ผลของการเปิดตัวรายย่าน D-083 ต่อ pillars, preset และหน้าที่บ้าน (SF-13 · P2-F06-T02)

1. **หน้าที่บ้านกลายเป็นประสบการณ์แรกของคนส่วนใหญ่ ไม่ใช่กรณีขอบ** · สามย่านเป็นส่วนเล็กของพื้นที่เล่น คนที่เปิดแอปจากบ้านนอกสามย่านจะเจอสถานะไกลหรือนอกย่านเปิดตัวก่อน · ผล: หัวข้อ 7 ต้องได้คุณภาพระดับเดียวกับ core loop (flow, copy, อวตาร, หน้า role) และ product-manager วัดอัตราปิดแอปบนหน้าจอนี้แยกตาม reason (GR-2) · เป้า "ได้รางวัลก้อนแรกใน 10 นาที" นับเฉพาะคนที่เริ่มในสถานะใกล้ (F06 A-P2-F06-T02-2) ไม่เช่นนั้นตัวเลขจะวัดภูมิศาสตร์แทน onboarding
2. **P2 "มาถึงแล้วต้องได้เล่น" ขึ้นกับเวลาทำการและช่วงเลเวลของ dungeon นำร่อง** · onboarding แนะนำเฉพาะแห่งที่เปิดอยู่ (D-089) และ playtest เดินเฉพาะเช้าและเย็น (D-093) · ข้อกำหนดต่อ level-designer: แต่ละย่านเปิดตัวต้องมี dungeon ที่ช่วงเลเวลครอบเลเวล 1 และเปิดทั้งสองช่วงเวลาของ playtest อย่างน้อยหนึ่งแห่ง และไม่มี level band ใดที่พึ่ง dungeon เดียว (N-04)
3. **P5 "กรุงเทพจริง" และความหลากหลายของ preset** · พระนครตัดวัง ศาสนสถาน และพื้นที่ราชพิธีออกมาก (D-083, D-006) ที่เหลือเป็นลานเมือง ริมน้ำ และสวนเล็ก ปทุมวันมีสวนใหญ่ บางรักเป็นสวนเล็กและริมน้ำ · ผล: preset สวนเล็กและริมน้ำจะเป็นสัดส่วนใหญ่ของ run ใน Phase 2 · drop table ทุก preset ต้องมียา (D-089) และตัวคูณ dungeon เล็กต้องไม่ทำให้ยาหายากจนไม่เห็นยาอัตโนมัติใน playtest (systems-designer ตรวจใน P2-F05-T01)
4. **หน้าที่บ้านเพิ่มการลงทะเบียนรายเขต** (D-073) สำหรับคนในพื้นที่เล่นที่อยู่นอกย่านเปิดตัว · ไม่มีรางวัล ไม่มีพิกัด ไม่มีช่องพิมพ์ ไม่แสดงจำนวนใน Phase 2 · ความต้องการระดับเขตนี้เป็น input ของ F23
5. **ไม่เปลี่ยน:** gate, auto-retreat, เกณฑ์ไกล (ยังผูกกับ route factor ไม่ผูกกับย่าน), กฎห้ามให้รางวัลที่บ้าน (7.3) · ข้อห้ามข้อ 3 ของ 7.3 ยังบังคับ: ห้ามแก้ปัญหาย่านน้อยด้วยการดึงรอยแยกมาใกล้บ้านหรือ dungeon เสมือน

ทุก design gate (`design/reviews/F<nn>-design-gate.md`) ตรวจตามลำดับนี้ และเขียนผลรายข้อ
1. ฟีเจอร์ช่วยให้คนเดินมากขึ้นหรือเดินได้นานขึ้นอย่างไร (หัวข้อ 1) ตอบไม่ได้ = NEEDS_CHANGES
2. ผ่านเกณฑ์ "ละเมิดเมื่อ" ของ P1–P5 ทุกข้อ (หัวข้อ 2)
3. ผ่าน NN-1 ถึง NN-8 (หัวข้อ 4) · ข้อใดตกเป็น finding `blocking: yes`
4. ไม่มีสิ่งที่ตัดออกจาก v1 ในรูปแบบใด (หัวข้อ 5)
5. ถ้าฟีเจอร์แตะ onboarding หรือการปลดระบบ: ตรงกับหัวข้อ 6 และอ้าง `config: unlocks.<system>`
6. ถ้าฟีเจอร์แตะหน้าที่บ้าน: ผ่านข้อห้ามในหัวข้อ 7.3
7. ข้อขัดแย้งที่เหลือตัดสินด้วยหลักการ 5 ข้อตามลำดับ (หัวข้อ 3) และเขียนหลักการที่ใช้ไว้ในรายงาน

การเปลี่ยนเอกสารนี้: game-director แก้ได้ภายในกรอบ GDD · การเพิ่ม ลด หรือเปลี่ยนความหมายของ pillar หรือ non-negotiable ต้องผ่าน HUMAN (เหมือนการยืนยันครั้งแรกใน P1-F03-T26)
