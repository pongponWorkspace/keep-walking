## 1. อุปกรณ์และการเตรียมเครื่อง

### 1.1 ต้องมี
- มือถือ Android 1 เครื่อง (เบราว์เซอร์ **Chrome**) และ iPhone 1 เครื่อง (เบราว์เซอร์ **Safari**) — ต้องเดินให้ครบทั้งสองเครื่อง เดินพร้อมกันในรอบเดียวกันได้ (คนละมือ/คนละกระเป๋า)
- URL ตัวอย่าง (preview URL) ที่ทีมส่งให้ก่อนวันเดินจริง — จะมีรูปแบบ `https://keep-walking-preview.pages.dev` (ทีมจะยืนยันของจริงอีกครั้ง)
- กล้องอีกเครื่อง (มือถือเครื่องที่ 3 หรือกล้องธรรมดา) สำหรับถ่ายจอกลางแดด (ข้อ 8)
- เพื่อนร่วมเดินอย่างน้อย 1 คน, น้ำดื่ม, หมวก/ร่ม, พาวเวอร์แบงก์ถ้ามี
- ไฟล์นี้ + `field-walk-form.md` เปิดอ่านได้ระหว่างเดิน (โหลดไว้ล่วงหน้าเผื่อสัญญาณเน็ตไม่ดี)

### 1.2 เตรียมเครื่องก่อนออกจากบ้าน (ทำทีละเครื่อง)

| ขั้น | Android (Chrome) | iPhone (Safari) |
| --- | --- | --- |
| ก. ชาร์จเต็ม | ชาร์จถึง 100% | ชาร์จถึง 100% |
| ข. ปิดโหมดประหยัดแบต | ตั้งค่า > แบตเตอรี่ > ปิด "โหมดประหยัดแบตเตอรี่" | ตั้งค่า > แบตเตอรี่ > ปิด "โหมดประหยัดพลังงาน" (Low Power Mode) |

### 1.3 เวลาที่ควรเดิน
- ช่วง **10:00–15:00 น.** วันที่แดดจัด ไม่มีฝน (ดูเหตุผลและกฎหยุดในกรณีฝน/ร้อนจัดใน `safety-briefing.md`)
- ไปสวนสาธารณะที่มีคนเดินพลุกพล่านตามปกติ 1 แห่ง และซอยแคบที่มีตึกสองข้าง (บังท้องฟ้าบางส่วน) 1 แห่ง

## 2. คำศัพท์และภาพรวม (อ่านก่อนเริ่ม)

| คำ | ความหมายแบบง่าย |
| --- | --- |
| **preview URL** | ที่อยู่เว็บที่ทีมส่งให้ เปิดในเบราว์เซอร์ปกติ ไม่ต้องติดตั้งแอป |
| **HUD** | แผงตัวเลขเล็ก ๆ ที่ปรากฏบนจอเมื่อเปิดด้วย `?hud=1` ในความเป็นจริงจะเห็นเป็นกล่องข้อความสั้น ๆ อัปเดตเองทุก 1 วินาที กับปุ่ม 2 ปุ่มและช่องกรอกตัวเลขแบต |
| **session** | การเปิดหน้าเว็บ 1 ครั้งจนถึงตอนที่ปิด/รีโหลดหน้า HUD จะนับตัวเลขสะสม "ตั้งแต่เปิดหน้านี้" เท่านั้น — **รีโหลดหน้า = เริ่มนับใหม่หมด** |
| **segment** | ช่วงกิจกรรมที่ตั้งใจแยกกัน (เดินหลัก 20 นาที, นั่งม้านั่งนิ่ง 5 นาที, วางบนโต๊ะนิ่ง 5 นาที) เครื่องมือรุ่นนี้ยังแยก segment อัตโนมัติในไฟล์ไม่ได้ (ดูข้อ 11) จึงต้อง **เปิดหน้าเว็บใหม่ 1 ครั้งต่อ 1 segment ที่อยากวัดแยก** ตามขั้นตอนด้านล่าง |
| **follow-mode (โหมดตามตัว)** | กล้องแผนที่เลื่อนตามจุดตำแหน่งเราอัตโนมัติ เปิดอยู่เป็นค่าเริ่มต้นแล้ว (ปุ่มจะขึ้นว่ากำลังตามตัวอยู่) |
| **export** | การกดปุ่มเพื่อดาวน์โหลดไฟล์ผลลัพธ์ลงเครื่อง (ไม่มีการอัปโหลดออกนอกเครื่องเอง) |

### ภาพรวม: จะทำอะไรบ้างในวันเดิน (ต่อเครื่อง ต่อสถานที่)

1. เปิดแอปครั้งแรกแบบ cache ว่าง (ข้อ 3) → ได้ session หลัก
2. เดินในสถานที่นั้น 30 นาที ต่อเนื่องใน session เดียวกัน (ข้อ 5 หรือ 7): 20 นาทีแรกจอเปิดตลอด + เดิน pan/zoom ตามสคริปต์ช่วงต้น, ที่เหลือ ~10 นาทีเก็บมือถือในกระเป๋า → กด export summary ก่อนปิด/รีโหลดหน้า
3. เปิดหน้าเว็บใหม่ (session ใหม่) ทำ segment นิ่ง 2 อัน อันละ 5 นาที: นั่งม้านั่งถือมือถือในมือ, วางมือถือนิ่งบนโต๊ะ/พื้นราบ → export แยกแต่ละอัน (ข้อ 6) — ทำครั้งเดียวพอ ไม่ต้องทำซ้ำทั้งสวนและซอย เลือกทำที่ไหนก็ได้ที่สะดวก
4. ถ่าย screenshot ป้ายไทย 3 ระดับซูม (ข้อ 8.2) และถ่ายรูปจอกลางแดดด้วยกล้องอีกเครื่อง (ข้อ 8.1)
5. ทำครบทั้งสวนและซอย ทำครบทั้ง Android และ iPhone (รวม 4 ชุดหลัก: สวน-Android, สวน-iPhone, ซอย-Android, ซอย-iPhone)
6. กรอกผลลง `field-walk-form.md` (1 ไฟล์ต่อสถานที่ต่อเครื่อง) แนบไฟล์ summary CSV ที่ export ได้

## 3. ขั้นตอนที่ 1 — เปิดแอปครั้งแรกต่อเครื่อง (cache ว่าง, ทำครั้งเดียวต่อเครื่องต่อวัน)

ตัวเลข S4–S8 (เวลาแผนที่ขึ้น, ขนาดข้อมูล) ต้องวัดตอน "เครื่องยังไม่เคยโหลดหน้านี้มาก่อน" วิธีที่ง่ายที่สุดสำหรับคนที่ไม่ถนัดเทคนิคคือเปิดด้วยแท็บส่วนตัว/ไม่ระบุตัวตน (ไม่ต้องไปหาเมนูล้างข้อมูลเว็บไซต์):

- **Android Chrome:** แตะจุดสามจุด (⋮) มุมขวาบน → "แท็บที่ไม่ระบุตัวตน" (Incognito tab) → เปิดแท็บใหม่
- **iPhone Safari:** แตะไอคอนแท็บ (สี่เหลี่ยมซ้อนกัน) มุมล่างขวา → แตะ "ส่วนตัว" (Private) ที่แถบด้านล่างให้ไฮไลต์ → แตะ "+" เพื่อเปิดแท็บใหม่

ขั้นตอน:

1. ในแท็บส่วนตัว พิมพ์ที่อยู่ตามนี้ (แทน `<PREVIEW_URL>` ด้วย URL จริงที่ทีมส่งให้):
   ```
   <PREVIEW_URL>/?loc=web&hud=1
   ```
2. เบราว์เซอร์จะถามขออนุญาตใช้ตำแหน่ง — แตะ **"อนุญาต" / "Allow"** และเลือก **"ระหว่างใช้แอป" / "While Using App"** (ไม่ใช่ "อนุญาตครั้งเดียว/Allow Once" เพราะจะถามซ้ำระหว่างเดิน)
   - **สำคัญมาก (iPhone):** ถ้ามีตัวเลือก **"ตำแหน่งที่แม่นยำ" (Precise Location)** ต้องเปิดไว้ (ON) เสมอ — ถ้าปิด ตำแหน่งจะคลาดเคลื่อนหลักร้อย-พันเมตร วัดผลไม่ได้เลย ถ้าพลาดกดปิดไปแล้ว แก้ที่ ตั้งค่า > ความเป็นส่วนตัวและความปลอดภัย > บริการหาตำแหน่ง > Safari Websites > เปิด Precise Location
   - **สำคัญมาก (Android):** ถ้ามีตัวเลือก "ตำแหน่งที่ชัดเจน/แม่นยำ" กับ "โดยประมาณ" ให้เลือก **แม่นยำ/Precise** เสมอ
3. รอจนแผนที่ขึ้น (นี่คือตัวเลข S4 "เวลาแผนที่แรกขึ้น" — ไม่ต้องจับเวลาเอง HUD คำนวณให้)
4. จะเห็นจุดสีแสดงตำแหน่งตัวเองพร้อมวงกลมรอบ ๆ (ระยะ accuracy) และแผงตัวเลข HUD ปรากฏ (มักอยู่ด้านล่างจอ) พร้อมปุ่ม "Export summary CSV", "Export raw trace (opt-in)" และช่องกรอกตัวเลข "battery %"
5. **หมายเหตุโหมดตามตัว (follow-mode):** สไตล์แผนที่ตั้งจุดกึ่งกลางเริ่มต้นไว้ที่สนามหลวง ซึ่งอยู่นอกพื้นที่ tile ตัวอย่างที่ทดสอบ — ถ้าเปิดแอปแล้วเห็นแผนที่ว่างเปล่าหรืออยู่ผิดที่สักครู่ อย่าตกใจ ให้รอสัญญาณ GPS 2–3 วินาที กล้องจะเลื่อนมาที่ตัวเราเองอัตโนมัติ (โหมดตามตัวเปิดอยู่แล้วเป็นค่าเริ่มต้น สังเกตจากปุ่มโหมดตามตัวในมุมจอที่ขึ้นสถานะ "กำลังตาม") ถ้าแผนที่ไม่เลื่อนมาเองภายใน 15 วินาที ให้แตะปุ่มโหมดตามตัวเพื่อเปิดเอง แล้วบันทึกไว้ในฟอร์มว่าเจอเหตุการณ์นี้
6. กรอกตัวเลขแบตเริ่มต้นที่จดไว้ (ข้อ 1.2) ลงในช่อง **"battery %"** ของ HUD ตอนนี้เลย (ปุ่มมี id `#hud-manual-battery` ถ้าถามหา element — ไม่ต้องกดอะไรเพิ่ม พิมพ์ตัวเลขแล้วกด Enter/ออกจากช่องพอ)

## 4. ขั้นตอนที่ 2 — วิธีอ่าน HUD และปุ่ม export

ไม่ต้องเข้าใจทุกตัวเลขในกล่อง HUD ระหว่างเดิน แค่รู้ 3 อย่างนี้พอ:

1. **กล่องตัวเลขจะขยับเองทุกวินาที** — เห็นตัวเลขเปลี่ยน แปลว่าเครื่องกำลังเก็บข้อมูลอยู่ปกติ ไม่ต้องกดอะไร ปล่อยจอไว้เฉย ๆ ระหว่างเดิน (ยกเว้นช่วง pan/zoom และช่วงกระเป๋าตามสคริปต์)
2. **ช่องกรอกแบต (`battery %`)** — กรอกเลข % แบตที่เห็นจากแถบสถานะทุกครั้งที่คู่มือบอกให้กรอก (ต้นและท้ายของแต่ละ session) จำเป็นมากสำหรับ iPhone เพราะเว็บอ่านค่าแบตของ iPhone เองไม่ได้
3. **ปุ่ม export มี 2 ปุ่ม อย่าสับสน**
   - **"Export summary CSV"** — ปุ่มหลักที่ต้องกดทุก session (ไม่มีพิกัด ปลอดภัย commit ได้) ไฟล์ชื่อ `summary-<รหัส>.csv` จะถูกดาวน์โหลดลงเครื่อง (ปกติไปอยู่ในโฟลเดอร์ Downloads)
   - **"Export raw trace (opt-in)"** — ปุ่มทางเลือก มีพิกัดจริงอยู่ในไฟล์ **กดเฉพาะเมื่ออ่านและยินยอมข้อความในข้อ 9 ก่อนแล้วเท่านั้น** ไม่บังคับ

**กติกาสำคัญ: กดปุ่ม "Export summary CSV" ทุกครั้งก่อนจะปิดแท็บหรือรีโหลดหน้า** เพราะตัวเลขทั้งหมดนับจากตอนเปิดหน้านี้เท่านั้น ปิด/รีโหลดโดยไม่ export แปลว่าข้อมูล session นั้นหายหมด ต้องเดินใหม่

หลัง export แต่ละครั้ง ไฟล์ CSV จะอยู่ในโฟลเดอร์ดาวน์โหลดของเครื่อง — ให้ส่งไฟล์นั้นมาเก็บตามข้อ 10 (ตั้งชื่อใหม่ตามกฎก่อนส่ง อย่าลบไฟล์ต้นฉบับจนกว่าจะยืนยันว่าย้ายสำเร็จ)

## 5. ขั้นตอนที่ 3 — เดินในสวน 30 นาที (session หลักของสวน)

ทำต่อจากข้อ 3 (เปิดแอปครั้งแรก) ใน session เดียวกัน ไม่ปิดหน้าจนกว่าจะ export เสร็จท้ายข้อนี้ เลือกสวนสาธารณะที่มีคนเดินตามปกติ พื้นที่เปิดโล่งพอสมควร (ไม่ใช่ใต้อาคาร)

### 5.1 นาทีที่ 0–1: ทดสอบ pan/zoom (ป้อนข้อมูล S1)
ใช้นิ้วป้าย (pan) แผนที่ไปมาและซูมเข้า-ออก (บีบนิ้ว/ขยายนิ้ว) สลับกันต่อเนื่องอย่างน้อย **60 วินาที** ยืนอยู่กับที่ตอนทำข้อนี้ได้ ไม่ต้องเดิน — นี่คือช่วงที่ HUD วัดความลื่นของแผนที่ตอนป้าย/ซูม

### 5.2 นาทีที่ 1–20: เดินต่อเนื่อง จอเปิดตลอด (ป้อนข้อมูล S2, S9, S11, S12, S13, S14, S15)
- เริ่มเดินความเร็วปกติ (ไม่วิ่ง ไม่หยุดนานเกิน 1 นาทีต่อครั้ง) ไปตามทางเดินในสวน ให้แผนที่ตามตัวเราไปเรื่อย ๆ (โหมดตามตัวยังเปิดอยู่)
- **ถือมือถือในมือ จอเปิดตลอด ห้ามเก็บกระเป๋าช่วงนี้** ต้องได้อย่างน้อย 20 นาทีติดต่อกันแบบนี้ (นาทีที่ 1 ถึงนาทีที่ 20 นับจากตอนเริ่มเดินข้อ 5.1)
- ระหว่างนี้ไม่ต้องกดอะไรที่จอ ปล่อยให้ HUD เก็บข้อมูลไปเรื่อย ๆ (ยกเว้นถ้าคู่มือข้อ 8 บอกให้แวะถ่ายภาพป้ายไทย/กลางแดดสั้น ๆ ระหว่างเดิน)
- 60 วินาทีแรกของ 20 นาทีนี้เป็นช่วง "warm-up" ของ GPS ทีมจะตัดออกตอนอ่านค่า accuracy ไม่ต้องทำอะไรพิเศษ เดินตามปกติ

### 5.3 นาทีที่ 20–30: เก็บมือถือในกระเป๋า (ป้อนข้อมูล I2, สังเกตพฤติกรรมจอล็อก)
- เดินต่อไปในสวน แต่คราวนี้ **เก็บมือถือลงกระเป๋ากางเกงหรือกระเป๋าสะพาย** (จอจะดับ/ล็อกเองตามปกติของเครื่อง) เดินต่อไปอีกประมาณ 10 นาที
- **นี่คือ "screen-lock/pocket test" แบบสังเกตอย่างเดียว** (ไม่มีเกณฑ์ผ่าน/ไม่ผ่านใน spike นี้ เพราะจอพกกระเป๋าจริงเป็นงานของ Phase 2) สิ่งที่ต้องสังเกตแล้วจดในฟอร์ม: จอดับ/ล็อกเองไหม กี่วินาทีหลังเก็บกระเป๋า, พอหยิบมือถือขึ้นมาใหม่ตอนจบช่วงนี้ แผนที่/จุดตำแหน่งกลับมาทำงานเองไหมหรือค้าง, มีข้อความแจ้งเตือนอะไรขึ้นบนจอไหม
- ครบเวลารวม 30 นาที (5.1+5.2+5.3) แล้วหยิบมือถือขึ้นมา **อย่าเพิ่งปิดหน้าจอ**

### 5.4 จบ session: export
1. กรอก % แบตปัจจุบันลงช่อง `battery %` ของ HUD (แบตท้าย session)
2. กดปุ่ม **"Export summary CSV"**
3. ปิดหรือรีโหลดหน้าได้แล้ว (ถ้าจะทำ raw trace แบบ opt-in ต่อ ให้กดปุ่มนั้นก่อนปิดหน้า — ดูข้อ 9)
4. บันทึกไฟล์ CSV ที่ได้ตามข้อ 10 ทันที ก่อนลืมว่าไฟล์ไหนของสวนหรือของซอย

## 6. ขั้นตอนที่ 4/5 — ทดสอบนิ่ง: "stationary" ม้านั่ง 5 นาที + "table" โต๊ะ 5 นาที

ทำ **ครั้งเดียวต่อเครื่อง** (ไม่ต้องทำซ้ำทั้งสวนและซอย) เลือกทำตอนไหนก็ได้ที่สะดวก เช่น ก่อนเริ่มเดินสวน หรือระหว่างพักที่ร่มในสวน เพราะแต่ละอันต้องเป็น session แยกของตัวเอง (เปิดหน้าเว็บใหม่) ให้ export คนละไฟล์กัน

### 6.1 "stationary" — นั่งม้านั่งถือมือถือในมือ 5 นาที (ป้อนข้อมูล I1)
1. เปิดหน้าเว็บใหม่ (session ใหม่ `?loc=web&hud=1` เหมือนเดิม — ไม่ต้องเป็นแท็บส่วนตัวรอบนี้ก็ได้ เพราะไม่ได้วัด S4-S8 รอบนี้) รอสัญญาณจนจุดตำแหน่งขึ้น
2. นั่งลงบนม้านั่งในสวน (หรือที่นั่งใด ๆ กลางแจ้ง) **ถือมือถือไว้ในมือตามปกติเหมือนกำลังจะเดิน** (ไม่วางนิ่งบนตัก) นั่งนิ่งที่สุดเท่าที่ทำได้ ไม่เดิน ไม่ลุก เป็นเวลา **5 นาทีเต็ม**
3. ครบ 5 นาที กดปุ่ม **"Export summary CSV"** — ไฟล์นี้คือชุด "stationary" (ตั้งชื่อไฟล์ตามข้อ 10)
4. เหตุผล: มือที่ถือสั่นตามธรรมชาติทำให้ GPS รายงานตำแหน่งขยับเล็กน้อยทั้งที่ไม่ได้เดิน (jitter) ทีมต้องรู้ว่าการนั่ง/ยืนคุยโทรศัพท์เฉย ๆ จะไม่ถูกนับเป็นระยะเดินเกิน 50 เมตรใน 5 นาทีจนได้รางวัลปลอมในอนาคต — ดูค่า `path_length_m` ในไฟล์ CSV ที่ export ได้ (ช่อง `stationary_5min_accum_m` ของไฟล์รุ่นนี้ยังว่างเสมอ เป็นข้อจำกัดที่รู้อยู่แล้ว ใช้ `path_length_m` แทนได้)

### 6.2 "table" — วางมือถือนิ่งบนโต๊ะ/พื้นราบ 5 นาที (ป้อนข้อมูล I1 กรณีเทียบ)
1. เปิดหน้าเว็บใหม่อีกครั้ง (session ใหม่อีกอัน)
2. วางมือถือนิ่งสนิทบนโต๊ะหรือพื้นราบกลางแจ้ง (หน้าจอหงายขึ้น ไม่มีใครแตะหรือถือ) ปล่อยทิ้งไว้ **5 นาทีเต็ม** โดยไม่มีการสั่นจากมือคน
3. ครบ 5 นาที หยิบขึ้นมา กดปุ่ม **"Export summary CSV"** — ไฟล์นี้คือชุด "table"
4. เหตุผล: เทียบกับข้อ 6.1 เพื่อแยกว่า jitter ที่เห็นมาจาก "มือสั่นตามธรรมชาติ" หรือมาจากตัวเครื่อง/GPS เองล้วน ๆ

## 7. ขั้นตอนที่ 6 — เดินในซอย 30 นาที (session หลักของซอย)

เลือกซอยแคบที่มีตึกหรือกำแพงสองข้าง (บังท้องฟ้าบางส่วน) เป็นเงื่อนไขจริงของกรุงเทพฯ ที่ต้องวัด (S10) ทำเหมือนข้อ 5 ทุกอย่าง (เปิดแท็บใหม่ตามข้อ 3 ก่อน เพื่อวัด cache ว่างของสถานที่นี้ด้วย) โดยสลับลำดับดังนี้:

1. เปิดหน้าเว็บใหม่ (แท็บส่วนตัว/ไม่ระบุตัวตนอีกครั้ง เพื่อ cache ว่าง) ที่ `<PREVIEW_URL>/?loc=web&hud=1` รอแผนที่ขึ้น กรอกแบตเริ่มต้น
2. นาทีที่ 0–1: pan/zoom 60 วินาที เหมือนข้อ 5.1
3. นาทีที่ 1–20: เดินต่อเนื่องในซอย จอเปิดตลอด ถือมือถือในมือ (เหมือนข้อ 5.2) — **นี่คือช่วงที่ป้อนข้อมูล S10 (accuracy ในซอย) โดยตรง** เดินความเร็วปกติ ไม่หยุดนานเกิน 1 นาที
4. นาทีที่ 20–30: เก็บมือถือในกระเป๋า เดินต่อ (เหมือนข้อ 5.3) สังเกตพฤติกรรมจอล็อกแบบเดียวกัน
5. กรอกแบตท้าย session, กดปุ่ม "Export summary CSV", บันทึกไฟล์ตามข้อ 10

ข้อควรระวังเพิ่มสำหรับซอย: ถ้าซอยแคบมากจนสัญญาณ GPS หายไปนาน (จุดตำแหน่งค้าง ไม่ขยับเกิน 30 วินาที) ให้เดินต่อตามปกติ **ไม่ต้องหยุดรอสัญญาณ** — ค่าที่หายไปคือสิ่งที่ทีมต้องการวัด (S13) บันทึกความรู้สึก/สังเกตไว้ในช่อง "ปัญหาที่เจอ" ของฟอร์มด้วย

## 8. งานเสริมระหว่างเดิน: กลางแดด, ป้ายไทย, การสั่น

ทำแทรกระหว่างข้อ 5 และ/หรือข้อ 7 (ช่วงนาทีที่ 1–20 ที่ถือมือถือในมืออยู่แล้ว) ใช้เวลาสั้น ๆ ไม่ต้องหยุดเดินนาน

### 8.1 ทดสอบอ่านจอกลางแดด (ป้อนข้อมูล S17 และ map-style 10.2) — ทำ 1 ครั้งต่อเครื่อง ตอนแดดจัดที่สุด (เที่ยง–บ่าย)
1. เปิดความสว่างจอ 100% และปิดปรับความสว่างอัตโนมัติ (ทำไว้แล้วตามข้อ 1.2ค) ยืนกลางแจ้งไม่มีร่มเงาบัง
2. ให้เพื่อนถือกล้อง (มือถือเครื่องที่ 3 หรือกล้อง) ถ่ายภาพหน้าจอที่ระยะ 35–40 ซม. มุมเอียงประมาณ 30 องศา (ท่าถือเดินจริง ไม่ใช่ถ่ายตรง ๆ) ขณะแผนที่แสดงตำแหน่งเราอยู่ ถ่าย 3 ภาพ: (S1) ซูมระดับปกติเห็นรอยแยก/dungeon ตัวอย่างและจุดตัวเอง, (S3) ซูมออกเห็นชื่อ dungeon และป้าย sponsored, (S4) ซูมออกไปถึงขอบเขตเล่น (เห็นโซนดำ/เส้นจังหวัด) — ถ้าเดินไม่ถึงขอบเขตเล่นจริง ถ่ายเท่าที่แผนที่แสดงได้แล้วบันทึกว่าไม่ถึง S4
3. ก่อนถ่าย ให้ผู้ถือมือถือลองอ่านเองก่อนว่า (1) อ่านชื่อถนนหลัก 2 ชื่อได้ไหม (2) แยกขอบรอยแยกออกจากพื้นสวนได้ไหม (3) เห็นจุดตัวเองภายใน 1 วินาทีไหม (4) อ่านชื่อ dungeon/ป้าย sponsored ได้ไหม (5) แยกโซนดำกับเส้นจังหวัดได้ไหม — บันทึกคำตอบแต่ละข้อในฟอร์มก่อน แล้วค่อยถ่ายภาพเก็บหลักฐาน
4. เก็บไฟล์ภาพที่ถ่ายได้ (ทั้งภาพสีต้นฉบับ) ไว้ในโฟลเดอร์ผลลัพธ์ตามชื่อในข้อ 10 ทีมงาน (art-director/tech-lead) จะเป็นคนแปลงเป็นขาวดำและตัดสินผลเองภายหลัง ไม่ต้องแปลงเอง
5. เสร็จแล้วเปิดปรับความสว่างอัตโนมัติกลับคืน (ประหยัดแบตช่วงที่เหลือ)

### 8.2 ป้ายชื่อภาษาไทยบนแผนที่ (ป้อนข้อมูล S16) — ทำระหว่างเดินทั้งสวนและซอย
ระหว่างเดิน (นาทีที่ 1–20) แวะหยุดสั้น ๆ 3 จุดเพื่อถ่าย screenshot หน้าจอ (กดปุ่ม power+volume down บน Android หรือ power+volume up บน iPhone) ที่ระดับซูมต่างกัน:
- ซูมประมาณ 14 (เห็นภาพกว้าง หลายถนน)
- ซูมประมาณ 16 (เห็นถนนหลักและซอยใหญ่)
- ซูมประมาณ 18 (เห็นซอยเล็ก/รายละเอียด)

ซูมโดยบีบนิ้ว/ขยายนิ้วบนแผนที่จนรู้สึกว่าใกล้ตรงกับ 3 ระดับนี้ (ไม่ต้องเป๊ะ) แล้วถ่าย screenshot ทันที ไม่ต้องนับจำนวนป้ายเองตอนเดิน แค่ถ่ายให้เห็นชื่อถนน/ซอยภาษาไทยชัดเจนที่สุดเท่าที่ทำได้ ทีมงานจะไล่นับป้ายจากภาพทีหลัง เก็บภาพทั้ง 3 ระดับซูม × 2 สถานที่ (รวม 6 ภาพอย่างน้อย) ไว้ตามข้อ 10

### 8.3 ทดสอบการสั่น (vibration check)
1. ระหว่างเดิน (ช่วงใดก็ได้ที่ถือมือถืออยู่) ลองสังเกตว่ามีการสั่นเกิดขึ้นเองจากแอปหรือไม่ในช่วงที่ทดสอบนี้ (build spike ปัจจุบันอาจยังไม่มีเสียง/สั่นจริงเพราะ cue เสียงเป็นงานของ Phase ถัดไป — ให้บันทึกตามที่เห็นจริง ไม่ต้องคาดเดา)
2. สิ่งที่ทีมต้องการยืนยันล่วงหน้า (ตามข้อมูลจาก audio direction): **iPhone Safari คาดว่าจะไม่สั่นเลย** (เว็บบน iOS ไม่รองรับการสั่น) ส่วน **Android Chrome คาดว่าจะสั่นได้ตามแพทเทิร์นที่ตั้งไว้** เมื่อมีการสั่นเกิดขึ้นจริง (ถ้ายังไม่มีฟีเจอร์นี้ใน build นี้เลยก็บันทึกว่า "ไม่มีการสั่นเกิดขึ้นเลยทั้งสองเครื่อง — ยังไม่ implement")
3. บันทึกผลที่สังเกตได้ (มี/ไม่มี, เครื่องไหน) ลงฟอร์ม ไม่ต้องตัดสินว่าผ่านหรือไม่ผ่าน เป็นข้อมูลสังเกตเท่านั้น

## 9. raw trace (มีพิกัดจริง) — ทางเลือก ต้องยินยอมเป็นลายลักษณ์อักษรก่อนทุกครั้ง

**ข้ามข้อนี้ได้ถ้าไม่อยากให้ข้อมูลตำแหน่งจริงของตัวเอง** การ export summary CSV (ข้อ 4–7) เพียงพอสำหรับงานทดสอบนี้แล้ว raw trace เป็นของแถมที่ช่วยทีมปรับสูตรเกมในอนาคตเท่านั้น

### สิ่งที่ควรรู้ก่อนตัดสินใจ (อ่านให้จบก่อนกดปุ่ม)
1. ไฟล์ raw trace มีพิกัด (ละติจูด/ลองจิจูด) ของเส้นทางที่เดินจริงในช่วง session นั้น แต่ **เครื่องมือจะตัดจุดเริ่มต้นและจุดสิ้นสุดของเส้นทางออกอัตโนมัติ 200 เมตรทั้งสองฝั่ง** (กันไม่ให้เห็นว่าบ้าน/จุดเริ่มต้นจริงของคุณอยู่ที่ไหน) และปัดพิกัดให้หยาบลงเหลือความละเอียดประมาณ 1 เมตร ไม่มีเวลาจริงหรือวันที่ในไฟล์ (มีแต่เวลานับถอยหลังจากจุดแรกของไฟล์)
2. ไฟล์นี้ **ดาวน์โหลดลงเครื่องเท่านั้น ไม่มีการอัปโหลดออกไปที่ไหนอัตโนมัติ**
3. ต้องนำไฟล์นี้ไปวางไว้ที่โฟลเดอร์ `qa/playtest/results/raw/` เท่านั้น (โฟลเดอร์นี้ถูกตั้งไว้ไม่ให้เข้า git/repo สาธารณะ) **ห้ามวางไว้ที่อื่น ห้ามส่งเข้าแชท ห้ามแนบในฟอร์มหรือไฟล์ที่จะ commit**
4. ทีม location-engineer อาจขอนำไฟล์นี้ไปแปลงเป็น "recorded trace" (ตัดพิกัดหยาบขึ้นอีกและเก็บไว้ใช้ทดสอบเกมในระยะยาว) — **จะทำก็ต่อเมื่อคุณตอบว่ายินยอมแยกอีกครั้งหนึ่งกับ orchestrator เท่านั้น** ถ้าไม่ตอบหรือปฏิเสธ ไฟล์จะไม่ถูกใช้ต่อ
5. คุณสามารถปฏิเสธข้อนี้ได้ทุกเมื่อโดยไม่มีผลอะไรกับงานที่เหลือ และสามารถยินยอมสำหรับบาง session แต่ปฏิเสธ session อื่นก็ได้ (เช่น ยินยอมเฉพาะสวน ปฏิเสธซอย)

### ข้อความยินยอม (อ่านออกเสียงหรืออ่านเองแล้วตอบ "ยินยอม" หรือ "ไม่ยินยอม" ในฟอร์ม)
> "ฉันเข้าใจว่าไฟล์นี้จะมีพิกัดตำแหน่งที่ฉันเดินจริงในช่วงเวลาที่ระบุ (ตัดต้น-ปลายเส้นทาง 200 เมตรและปัดความละเอียดแล้ว ไม่มีชื่อหรือข้อมูลระบุตัวตนอื่นอยู่ในไฟล์) ไฟล์จะถูกเก็บไว้ในเครื่องและโฟลเดอร์ที่ไม่เข้าระบบสาธารณะเท่านั้น ฉันยินยอมให้ทีมงานใช้ไฟล์นี้เพื่อทดสอบและปรับปรุงระบบเกม และฉันเข้าใจว่าฉันสามารถถอนความยินยอมนี้ได้ภายหลังโดยแจ้งทีมงาน"

ถ้ายินยอม: กดปุ่ม **"Export raw trace (opt-in)"** ก่อนปิดหน้าของ session นั้น (ต้องกดก่อนกด/แทน "Export summary CSV" หรือกดทั้งคู่ก็ได้ ลำดับไม่สำคัญ ขอแค่กดก่อนปิด/รีโหลดหน้า) ไฟล์ชื่อ `field-<รหัส>.trace.json` จะถูกดาวน์โหลดลงเครื่อง — ย้ายไปที่ `qa/playtest/results/raw/` ทันที

## 10. การบันทึกผลและตั้งชื่อไฟล์

**กฎที่ต้องจำ:** ไฟล์ที่มีพิกัดจริง (raw trace) ห้ามอยู่ที่อื่นนอกจาก `qa/playtest/results/raw/` เด็ดขาด เพราะ repo ของโปรเจกต์นี้เป็นสาธารณะ — ไฟล์ summary CSV และฟอร์มผล (ไม่มีพิกัด) วางที่ `qa/playtest/results/` ได้ตามปกติ

### 10.1 โครงสร้างไฟล์ที่ต้องได้ต่อ 1 รอบเดินจริง (สวนหรือซอย × Android หรือ iPhone)

```
qa/playtest/results/
  <YYYY-MM-DD>-park-android.md         ฟอร์มผลของสวน เครื่อง Android (คัดลอกจาก field-walk-form.md)
  <YYYY-MM-DD>-park-android-summary.csv   ไฟล์ export หลัก (20+10 นาที) ของรอบนี้
  <YYYY-MM-DD>-park-android-stationary.csv  (ทำครั้งเดียวต่อเครื่อง แนบซ้ำในทุกไฟล์ฟอร์มของเครื่องนั้นก็ได้)
  <YYYY-MM-DD>-park-android-table.csv       (เช่นเดียวกัน)
  <YYYY-MM-DD>-park-ios.md
  <YYYY-MM-DD>-park-ios-summary.csv
  <YYYY-MM-DD>-soi-android.md
  <YYYY-MM-DD>-soi-android-summary.csv
  <YYYY-MM-DD>-soi-ios.md
  <YYYY-MM-DD>-soi-ios-summary.csv
  raw/                                 (ถูก .gitignore) ใส่ field-<รหัส>.trace.json ที่นี่เท่านั้น ถ้ามี
```

- `<YYYY-MM-DD>` = วันที่เดินจริง (เช่น `2026-09-24`)
- ไฟล์ CSV ที่ดาวน์โหลดมาจะชื่อ `summary-<รหัส สุ่มยาว>.csv` — **เปลี่ยนชื่อไฟล์** เป็นรูปแบบด้านบนก่อนย้ายเข้าโฟลเดอร์ (อย่าลืมว่าไฟล์ไหนมาจากสวน/ซอย/นิ่ง/โต๊ะ เพราะไฟล์ไม่มีข้อมูลนี้อยู่ในตัวเอง — ดูข้อ 11 หัวข้อ "ข้อจำกัดที่รู้อยู่แล้ว")
- ถ่ายภาพ screenshot ป้ายไทย (ข้อ 8.2) และภาพกลางแดด (ข้อ 8.1) เก็บไว้ในโฟลเดอร์เดียวกันหรือโฟลเดอร์ย่อย `<YYYY-MM-DD>-<park|soi>-<device>-photos/` แล้วอ้างชื่อไฟล์ไว้ในฟอร์ม
- ถ้าไม่แน่ใจว่าจะย้ายไฟล์เข้า repo ยังไง (เช่น ไม่ถนัดใช้คอมพิวเตอร์/git) ให้ส่งไฟล์ทั้งหมดที่ได้ (ยกเว้น raw trace ที่มีพิกัด) ให้ orchestrator/ทีมงานทางช่องทางที่ตกลงกันไว้ แล้วให้ทีมช่วยย้ายเข้าตำแหน่งที่ถูกต้องแทน — **ห้ามส่งไฟล์ raw trace ผ่านแชทหรืออีเมลเด็ดขาด** ให้ทีมมารับที่เครื่องโดยตรงหรือใช้วิธีที่ orchestrator กำหนดเฉพาะสำหรับไฟล์ที่มีพิกัด

## 11. ปัญหาที่เจอบ่อยและควรทำอย่างไร

| เจอแบบนี้ | ทำแบบนี้ |
| --- | --- |
| ช่องกรอกแบต พิมพ์เป็นตัวเลขล้วน เช่น `82` | ห้ามพิมพ์เครื่องหมาย `%` ตาม พิมพ์ตัวเลข 0–100 เฉย ๆ |
| หน้าเว็บถามเรื่องบัตร/การชำระเงิน/ล็อกอินบัญชี/สมัครสมาชิก | **หยุดทันที ไม่กรอกอะไร** หน้านี้ควรเป็นแค่แผนที่ ไม่ต้องล็อกอินหรือจ่ายเงินอะไรเลย ถ้าเจอแบบนี้แจ้ง orchestrator ทันทีพร้อมภาพหน้าจอ |
| เปิด URL แล้วไม่เห็นแผงตัวเลข HUD เลย | ตรวจว่าพิมพ์ท้าย URL ถูกต้องว่า `?loc=web&hud=1` (ไม่มีช่องว่าง ไม่ใช่ `hud=true`) |
| แผนที่ขึ้นแต่เป็นพื้นเทาว่างเปล่า ไม่เห็นถนน/สวนเป็นภาพ (เห็นแค่จุดตัวเองลอยอยู่) | **นี่คือความเสี่ยงที่รู้อยู่แล้วจากการทดสอบในห้องแล็บ (ยังไม่เคยยืนยันบนมือถือจริง)** ถ่ายภาพหน้าจอเก็บไว้ บันทึกในฟอร์มว่าเจอ แล้วรอ 10–15 วินาทีดูว่าภาพขึ้นมาเองไหม ถ้าไม่ขึ้นเลยตลอด 1 นาที ให้แจ้ง orchestrator/tech-lead ก่อนเดินต่อ (อาจต้องหยุดรอ build ใหม่) — ไม่ใช่ความผิดของผู้เดินทดสอบ |
| ขออนุญาตตำแหน่งแล้วกด "ปฏิเสธ/Don't Allow" ไปโดยไม่ตั้งใจ | Android: แตะไอคอนกุญแจ/ตัว "i" ข้างที่อยู่เว็บ > สิทธิ์ > ตำแหน่ง > อนุญาต แล้วรีโหลดหน้า · iPhone: ตั้งค่า > Safari > ตำแหน่งที่ตั้ง (Location) > อนุญาตสำหรับเว็บไซต์นี้ แล้วรีโหลด |
| มีสายเรียกเข้าหรือสลับไปแอปอื่นระหว่าง session (ไม่ใช่แค่ล็อกจอ) | ข้อมูลช่วงนั้นจะขาดหาย ถือว่า session นั้นเสียบางส่วน ถ้ายังไม่ครบ 20 นาทีจอเปิดตลอด ให้เริ่ม session ใหม่สำหรับช่วงที่เหลือและบันทึกเหตุการณ์นี้ในฟอร์ม |
| ไม่แน่ใจว่าไฟล์ CSV ไหนเป็นของช่วงไหน (สวน/ซอย/นิ่ง/โต๊ะ) | เปลี่ยนชื่อไฟล์ทันทีหลัง export ทุกครั้งตามข้อ 10 ก่อนจะไปทำ session ถัดไป อย่าปล่อยให้ export หลายไฟล์ค้างอยู่ในโฟลเดอร์ดาวน์โหลดโดยไม่เปลี่ยนชื่อ |
| ป้ายไทยบนแผนที่อ่านไม่ออก/เป็นกล่องสี่เหลี่ยม (tofu) | ไม่ใช่ปัญหาของผู้เดิน ถ่าย screenshot เก็บไว้ตามปกติ (ข้อ 8.2) แล้วบันทึกในฟอร์มว่าเจอที่จุดไหน ทีมจะนำไปตัดสิน S16 เอง |
| แบตหมดเร็วผิดปกติจนกลัวจะไม่ครบ 30 นาที | ให้ความปลอดภัยมาก่อนเสมอ — ถ้าแบตวิกฤต ให้หยุดและ export เท่าที่ทำได้ บันทึกว่าหยุดกลางคันเพราะแบต ไม่ต้องฝืน |

### ข้อจำกัดที่รู้อยู่แล้วของเครื่องมือวัดรุ่นนี้ (ไม่ใช่ความผิดของผู้เดิน)

- คอลัมน์ `stationary_5min_accum_m` จะว่างเปล่าเสมอในทุกไฟล์ (ยังไม่ implement) ใช้คอลัมน์ `path_length_m` ของไฟล์ "stationary"/"table" แทนตามข้อ 6
