## 1. ปัญหาผู้เล่น (Problem statement)

**"ผมเปิดแอปมาครั้งแรก เจอแค่ปุ่มเริ่มเกมแล้วโยนเข้าโลกเลย ผมไม่รู้สึกว่านี่คือ 'บัญชีของผม' หรือ 'ตัวละครของผม' — มันเหมือนหน้าจอทดสอบมากกว่าเกมจริง"**

พรีวิวที่คนทดสอบเองในเครื่องจริงพบว่า flow เดิมของ F06 (เลือก class ทันทีแล้วเข้าแผนที่) ขาดจังหวะที่ทำให้ผู้เล่นรู้สึกเป็นเจ้าของตัวละครและเข้าใจโลกก่อนเริ่มเดิน — คนสั่งให้เพิ่ม 3 จังหวะใหม่ (login แบบ bypass, สร้างตัวละครมีชื่อของตัวเอง, เรื่องเปิดเกม 5 slide) และวางโครง main nav ที่รองรับฟีเจอร์ที่ยังไม่มาถึง (Upgrade/Shop/Party) แทนที่จะซ่อนไปเฉยๆ

ปัญหานี้มีสองด้านที่ต้องถือไปด้วยกัน:
1. **ความรู้สึกเป็นเจ้าของ (ownership)** — ชื่อตัวละครที่พิมพ์เอง + เรื่องเปิดเกม ทำให้ "นี่คือตัวละครของฉัน ไม่ใช่ของทดสอบ" โดยไม่ต้องมีระบบบัญชีจริง (ยังไม่มี server ใน Phase 2)
2. **ความคาดหวังที่ไม่บาน** — เพิ่ม 3 จังหวะใหม่ต้องไม่ดันเวลาก่อนถึงรางวัลก้อนแรกเกินเป้า 10 นาทีเดิมของ F06 (R-F10-4 ของ plan-sync) และปุ่ม login Google/Apple ต้องไม่ทำให้ผู้เล่นเข้าใจผิดว่ามีบัญชีจริงข้ามเครื่องได้ (R-F10-1)

## 3. ขอบเขตสิ่งที่ F10 ส่งมอบ (ตาม D-144..D-149)

- ปุ่ม "เริ่มเกม" เดียวแทนข้อความเปิด + แตะที่ไหนก็ได้ (D-144)
- จอ login: ปุ่ม Google/Apple เด่น + ลิงก์ email (login/register/forgot) — **bypass ฝั่ง client ทั้งหมด ไม่มี auth จริง ไม่เก็บ password/อีเมล** (D-145, auth จริงอยู่ F07/Phase 3)
- จอสร้างตัวละคร: เลือก class + ชื่อตัวละครพิมพ์เอง (มีตัวกรอง + ปุ่มสุ่ม + คำเตือนอย่าใช้ชื่อจริง) แทนที่ "class sheet" เดิมของ F06-R44 (D-146)
- เรื่องเล่า 5 slide หลังสร้างตัวละคร กด "ถัดไป" ทีละ slide จบด้วยปุ่ม "ออกไปลุย!" (D-147)
- map เป็นหน้าหลัก + bottom nav 5 ปุ่ม (Inventory, Upgrade, Map, Shop, Party) — Upgrade/Shop/Party แสดง "เร็วๆ นี้" + ไอคอน Setting มุมบนขวา (ตั้งค่าเดิม + ออกจากระบบ) (D-148)
- ลำดับ onboarding ใหม่ทั้งสาย: เริ่มเกม → login → age gate → consent ตำแหน่ง → permission เบราว์เซอร์ → สร้างตัวละคร → เรื่อง 5 slide → map (D-149) — **age gate มาก่อน consent เสมอตาม NN-7 ไม่เปลี่ยน**
- migration ผู้เล่นเดิมที่เคยผ่าน onboarding แบบ F06 เดิม (มี class ไม่มีชื่อ/account) ตามคำตัดสินของ spec T01: login → ตั้งชื่อ (class ล็อก) → เรื่อง → map, run ค้างเล่นจบก่อน (F10-R45–R48, D-152 — ปิดแล้ว ดูหัวข้อ 7)

## 5. Non-goals ของ F10

- **ไม่มี authentication จริง** — login ทุกวิธี (Google, Apple, email login/register/forgot) เป็น bypass ฝั่ง client ล้วน ไม่มี request ออกไป provider จริง ไม่มี session token ไม่มีการยืนยันตัวตนข้ามเครื่อง — auth จริงเป็นของ **F07 (Phase 3)**
- **ไม่เก็บหรือแสดงชื่อตัวละครให้ผู้เล่นอื่นเห็น** — ชื่อเก็บในเครื่องเท่านั้น (NN-4, D-146) ไม่มีในทุก telemetry event และไม่มี export
- **ไม่มีระบบเพื่อน/Nearby Party จริง** — nav ปุ่ม Party เปิดจอ "เร็วๆ นี้" เท่านั้น ของจริงเป็น F09 (Phase 3)
- **ไม่มีตลาด/ตีบวก/ร้าน NPC จริง** — nav ปุ่ม Upgrade/Shop เปิดจอ "เร็วๆ นี้" เท่านั้น ของจริงเป็น Phase 4 ขึ้นไป
- **ไม่แก้ปัญหา 10 นาทีแรกของ F06 ที่มีอยู่แล้ว** — F10 เพิ่มจังหวะก่อนหน้า ไม่เปลี่ยนกติกา HP/damage/auto-retreat/หน้าจอ fallback ของ F06
- **ไม่มี parental-consent flow ในแอปจริง** — สืบทอดสถานะเดิมจาก F06 PRD §5 (scaffold age gate 15+ เท่านั้น)
- **ไม่แก้ไฟล์ `studio/roadmap.md`** — F10 เป็นงานเพิ่มนอกรอบตามคำสั่งของคน ไม่ใช่การแก้แผน Phase ที่มีอยู่ (ดู `plan-sync-f10.md` §1)

## 6. คำถามที่ต้องตรวจก่อนหรือระหว่าง gate (ไม่ใช่คำถามภาคสนาม — playtest ของ F10 คนจัดการเอง ตาม D-149/P2-F10 ไม่มีงาน agent ใดแตะ `qa/playtest/`, `product/playtest/`)

1. เวลารวมของ 3 จังหวะใหม่ (login + สร้างตัวละคร + เรื่อง 5 slide) เมื่อรวมกับ F06 เดิม ยังอยู่ในงบ 10 นาทีก่อนรางวัลก้อนแรกไหม (ตรวจใน design gate T23 จาก flow จริง ไม่ใช่ playtest ใหม่)
2. ปุ่ม Google/Apple ที่เป็น bypass ทำให้ผู้เล่นเข้าใจผิดว่ามีบัญชีจริงหรือไม่ (R-F10-1) — ตรวจจาก copy ของ T11 ใน copy gate T20 ว่าไม่มีข้อความสัญญา sync/กู้คืนบัญชี
3. `filter_reject_count` แจกแจงอย่างไรจาก vector ทดสอบของ T04/T12 (ก่อนมีผู้เล่นจริงมาลอง) — ใช้เป็น proxy ล่วงหน้าของ "ตัวกรองเข้มไปหรือไม่" ก่อนเห็นข้อมูลจริง
