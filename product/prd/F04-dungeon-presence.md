## 1. ปัญหาผู้เล่น (Problem statement)

**"เกมต้องรู้ให้แน่ว่าฉันอยู่ในสวนหรือไม่ ไม่ใช่กะพริบไปมาเวลาฉันแค่เดินเลียบขอบสวนหรือคุยโทรศัพท์อยู่ริมทาง"**

Dungeon คือ polygon ของสถานที่สาธารณะกลางแจ้ง ผู้เล่นเดินเข้าออกได้ตลอดเวลาโดยไม่ได้ตั้งใจ (แวะร้านค้าปากทาง, เดินเลียบขอบสวนตามทางเท้าจริง, GPS drift ใกล้ตึกสูง) F04 ต้องตอบสามคำถามที่ทุกฟีเจอร์อื่นพึ่งพา:

1. ผู้เล่นอยู่ใน dungeon ไหนอยู่ ณ ขณะนี้ (อยู่ได้ทีละ 1 แห่งเท่านั้น แม้ polygon ซ้อนกัน)
2. ออกนอกกรอบแล้วนับว่า "ยังเล่นอยู่" ถึงเมื่อไหร่ก่อนตัดจบ run จริง (Active/Grace/Suspended/Ended)
3. dungeon แห่งนั้นเปิดให้เข้าตอนนี้หรือไม่ และถ้าไม่เปิดหรืออยู่ไกลเกินไป ผู้เล่นควรเห็นอะไร

ถ้า F04 ทำพัง ผลกระทบไม่ได้จำกัดแค่ตัวเอง — F05 (reward tick) และ F06 (HP/damage) คำนวณทุกอย่างจาก state ที่ F04 ผลิต ความผิดพลาดที่นี่แปลว่าเดินจริงแต่ไม่ได้ของ หรือได้ของทั้งที่เดินออกไปแล้ว ซึ่งเป็นความรู้สึก "เกมโกง" ที่ GDD เตือนไว้ตรงๆ ในหัวข้อ "ระบบกันตาย"

## 3. ขอบเขตสิ่งที่ F04 ส่งมอบ (ตาม roadmap Phase 2)

- point-in-polygon + เลือกเข้าได้ทีละ 1 dungeon พร้อม popup confirm (แสดงชื่อโซน **ไม่แสดงจำนวนคน** ตาม GD N-04/A-P2-PLAN-02-1)
- state machine **Active / Grace (≤3 นาที) / Suspended (3–15 นาที) / Ended (>15 นาที)** ตาม GDD "การเข้าและออก" — Grace และ Suspended ไม่ได้ reward tick แต่ run ไม่ขาด
- เวลาทำการจาก OSM `opening_hours` + กรอกเอง — dungeon ปิดแสดง "เวลาเปิดถัดไป" และเข้าไม่ได้ (ความปลอดภัยทางกายภาพ, GDD "เวลาทำการ")
- ข้อมูล dungeon นำร่อง 10–20 แห่งจากย่านเปิดตัว (พระนคร + ปทุมวัน + บางรัก ตาม D-083) — polygon, ช่วงเลเวล, preset, จุดปลายทางนำทางสาธารณะ
- หน้าแผนที่ dungeon ใกล้ตัว + นำทาง (ลูกศร/ระยะเส้นตรงแบบปัดขั้น, ไม่มีเส้นทางในแอป, ปุ่มเปิดแอปแผนที่ภายนอกไปยังจุดสาธารณะเท่านั้น ตาม A-P2-PLAN-01-3)
- ข้อมูลนี้เป็น input โดยตรงของ F06 (หน้าจอไกล/นอกพื้นที่) และ F05 (reward tick ต้องรู้ว่าอยู่ Active หรือไม่ก่อนตัดสิน gate)

## 5. Non-goals ของ F04

- **ไม่ออกแบบหน้าจอ fallback ของคนไกล/นอกพื้นที่** — เป็นของ F06 (หน้าจอนาที 0–10 ของคนใหม่) F04 ส่งแค่ข้อมูลระยะ/สถานะเปิดปิดให้ F06 ใช้
- **ไม่ตัดสินรางวัลใดๆ** — F04 ผลิตแค่ presence state ส่วนการตัดสิน movement gate และ tick เป็นของ F05 ทั้งหมด (C1-1: ผลบน client Phase 2 ไม่ใช่รางวัลจริง)
- **ไม่รองรับ dungeon ในอาคาร** (`floor_level`, `verification_mode: entry_exit`) — Phase 2 ทำเฉพาะ `continuous_gps` กลางแจ้ง ตาม non-negotiable ข้อ 5 ของ CLAUDE.md ฟิลด์ทั้งสองมีอยู่ใน data model แต่ยังไม่ใช้งานจริง
- **ไม่แสดงจำนวนคนในสถานที่** — Phase 2 ซ่อนจำนวนคนในทุก dungeon และทุกจังหวัด (A-P2-PLAN-02-1) แม้ในสถานะ Ended/summary ก็ไม่แสดง
- **ไม่มีระบบรายงาน/บล็อกสถานที่แบบเต็มรูป** — `dungeon_report_submitted` ประกาศชื่อ event ไว้แล้วแต่ moderation queue เต็มรูปเลื่อนไป F13/F15 (Phase 5)
- **ไม่คำนวณ GR-1 เป็นเกณฑ์เปิดตัวจริง** — F04 ใช้ GR-1 เป็นสัญญาณเฝ้าดูของ Phase 2 เท่านั้น เกณฑ์เปิดตัวจริงของ 3 ย่านเป็นของ PRD F01 §4 ที่ HUMAN ตัดสินไปแล้วใน D-083

## 6. คำถามที่ playtest ต้องตอบ

1. เดินเลียบขอบสวน/ตลาดจริงแล้ว state กะพริบ (Active↔Grace) บ่อยจนรำคาญไหม — ค่า Grace 3 นาทีพอไหมในสถานที่จริงที่ไม่ใช่ trace สังเคราะห์
2. ผู้เล่นเข้าใจ popup confirm ทันทีไหมว่ากำลังจะเข้า dungeon ไหน (โดยเฉพาะจุดที่ polygon ซ้อนกันสองแห่ง)
3. ปุ่มนำทางไปจุดปลายทางสาธารณะพาไปถึงจริงไหม หรือมีจุดที่ "ดูใกล้บนแผนที่แต่เดินเข้าไม่ถึงจริง" (ตาม GDD "ความปลอดภัยทางกายภาพ" เรื่อง radius ใจกว้าง)
4. เจอ dungeon ที่ปิดเพราะเวลาทำการไหม และข้อความ "เวลาเปิดถัดไป" ชัดพอให้ตัดสินใจกลับหรือรอไหม
5. GPS drift ใกล้ตึกสูงหรือใต้ทางด่วน (ถ้ามีในเส้นทางเดิน) ทำให้เข้า/ออก dungeon ผิดพลาดไหม

## 7. ข้อจำกัดของ playtest (บังคับอ่านคู่กับผลทุกครั้ง)

- **ผลบน client ใน Phase 2 ไม่ใช่รางวัลจริง** (C1-1/C1-5) — สิ่งที่ผู้เล่นเห็นว่า "เข้า dungeon สำเร็จ" เป็น state ฝั่ง client ล้วนๆ ยังไม่มี server ยืนยันซ้ำ ห้ามตีความว่าผ่านการโกงไม่ได้แล้วในระดับ production
- **ไม่แสดงจำนวนคนในสถานที่ต่อผู้เล่น** ตลอด Phase 2 — คำถามข้อ 2 ข้างต้นจึงวัดได้แค่ "เข้าใจว่าเข้าโซนไหน" ไม่ใช่ "รู้สึกว่ามีคนอยู่ด้วยไหม" (เป็นของ Phase 3 F09)
- **ผู้ร่วม playtest ภาคสนามอายุ 15–17 เข้าร่วมได้** ตาม D-092 (ทางเลือก ข) โดยต้องมีแบบฟอร์มยินยอมของผู้ปกครองแบบกระดาษที่เซ็นก่อนเดินจริง เดินกับทีมหรือผู้ใหญ่ตลอดเวลา อายุต่ำกว่า 15 ปีไม่รับเข้าร่วมไม่ว่ากรณีใด แบบฟอร์มที่เซ็นแล้วเก็บนอก git เด็ดขาด (ห้าม commit หรือสแกนเข้า repo) — นี่คือการแก้จากสมมติฐานเดิม A-P2-PLAN-01-5 ("ผู้ใหญ่ 18+ เท่านั้น") ที่ยังไม่ได้ปิดตอนวางแผน
